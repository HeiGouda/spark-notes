## 1. 产品概述

### 1.1 定位

Spark 是一款面向**个人单用户**的桌面端 Markdown 笔记软件。核心诉求：

- 记录体验接近 Typora：所见即所得的 Markdown 编辑，代码块语法高亮。
- 数据完全由用户掌控：笔记就是磁盘上的普通 `.md` 文件，思维导图和流程图是同一文件夹里的 Mermaid 文本文件（见 5.18），拷走文件夹即可迁移。
- 可同步到用户自己的存储（WebDAV 或 Git 远程仓库），多台电脑间保持一致；也可用 Git 在本地做版本管理。
- **轻量、高性能**：低内存占用、快速启动、大库下搜索依旧迅速。
- **可选的 AI 辅助**：用户自己配置 AI 服务（OpenAI 兼容接口），只在用户主动点击时发送内容（见 5.16、5.17）。

### 1.2 目标用户

仅作者本人（单用户，无账号体系，无协作）。

### 1.3 运行平台

- Windows、macOS 13 及以上。
- 以 Windows 为主要验证平台。
- 安卓可以查看笔记、导图和流程图，也可以管理云端书架、阅读电子书、划线记笔记，并使用单独配置的 AI 对话。普通笔记、导图和流程图仍然只读，不写回云端。不上架应用商店。

### 1.4 非目标（明确不做）

- 多用户、账号注册登录、多人协作/共享。
- 自建同步服务端。
- 富文本/私有格式存储、块编辑器数据模型。
- 在手机上编辑普通笔记、导图和流程图，以及把安卓版上架应用商店。
- 带 DRM 的电子书。

## 2. 技术选型

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 应用框架 | Tauri 2 | 使用系统 WebView，安装包不到 5MB（实测见 7.1），内存远低于 Electron |
| 后端 | Rust | 文件 IO、索引、同步等重任务放在原生侧 |
| 前端 | Vue 3 + TypeScript | — |
| 编辑器 | Milkdown（基于 ProseMirror） | 成熟的 Markdown 所见即所得方案，体验接近 Typora |
| 代码高亮 | Prism（`@milkdown/plugin-prism` + refractor） | Milkdown 官方插件直接集成；Shiki 需额外的 wasm 引擎与语法包，体积大得多 |
| 全文搜索 | SQLite FTS5 + 中文二元切分 | 本地索引，毫秒级查询；不依赖词典，安装包不增大 |
| 凭据存储 | 系统凭据库（Windows 凭据管理器 / macOS 钥匙串）；其他系统上保存凭据会失败 | 不明文保存 WebDAV 密码、Git 远程密码与 AI 的 API Key |
| AI 接口 | OpenAI 兼容的 Chat Completions 接口，Rust 侧用 `ureq` 发请求（SSE 流式输出） | 一套协议覆盖国内外主流服务商与本地模型；Key 不进入前端页面，也没有跨域问题；不新增 HTTP 依赖 |
| 一键整理（规则版） | 中英文空格用 `pangu`（无依赖，持续维护）；全角转半角、中文标点、行尾空格等几条确定的字符规则自行实现并有单元测试 | `zhlint` 自 2024-08 未更新，且依赖 `glob`、`chalk` 等命令行包，不适合打包进前端 |
| AI 对话的 Markdown 显示 | `markdown-it`（关闭 HTML）+ 现有的 Prism 代码高亮 | 成熟、体积小，默认不渲染 HTML，AI 回复里的标签不会被执行 |
| 思维导图与流程图（5.18） | Mermaid `mindmap` / `flowchart` 子集的解析与写回、思维导图的五种结构排版、流程图的自由画布（位置写在文件里；没有位置时和 AI 整理时由程序排版）均自行实现并有单元测试，不引入排版库 | 完整的 Mermaid 库有数 MB，超出安装包预算；只需读写支持的子集，且要保证写回时不改坏文件 |

原则：优先复用成熟开源组件，不自研编辑器与搜索引擎。

## 3. 数据与存储

### 3.1 笔记库（Vault）

- 一个笔记库 = 磁盘上的一个普通文件夹。
- 支持**多个笔记库**，可新建、打开已有文件夹、切换、从列表移除（不删除磁盘文件）。
- 笔记库内的文件夹结构即左侧目录结构。

### 3.2 目录布局

```
我的笔记库/
├── 工作/
│   ├── 周报.md
│   ├── 周报.assets/          # 附件（默认模式：与笔记同名的文件夹）
│   │   └── image-20260924.png
│   └── 项目上线流程.flow.mmd  # 流程图（见 5.18）
├── 个人/
│   ├── 读书笔记.md
│   └── 读书笔记 导图.mind.mmd # 思维导图（见 5.18）
├── assets/                   # 附件（可选模式：统一目录）
└── .ttnote/                  # 应用数据目录（隐藏）
    ├── config/               # 同步 ✅：收藏、排序方式与自定义顺序、文件时间记录、笔记库级设置
    ├── cache/                # 不同步 ❌：搜索索引等，可删除重建
    ├── history/              # 不同步 ❌：历史版本快照
    ├── trash/                # 不同步 ❌：回收站
    └── sync/                 # 不同步 ❌：同步状态记录
```

### 3.3 笔记文件格式

- 标准 Markdown（CommonMark + GFM 扩展：表格、任务列表、删除线等）。
- **文件名即标题**，正文不强制包含 `# 标题`。
- 元数据写在文件开头的 YAML Front Matter 中：

```markdown
---
tags: [工作, 周报]
created: 2026-09-24T15:00:00+08:00
---

正文内容……
```

- 标签同时支持 Front Matter 中的 `tags` 与正文内的 `#标签` 写法，两者合并展示。
- 用其他 Markdown 编辑器打开不丢失任何信息。
- 思维导图与流程图的文件格式见 5.18。

### 3.4 附件

- 支持粘贴、拖入图片及文件，自动复制到附件目录并插入相对路径引用。
- 附件存储位置可在设置中选择：
  - **默认**：笔记旁的同名文件夹 `笔记名.assets/`
  - 可选：笔记库根目录 `assets/`
- 笔记重命名/移动时，附件目录随之移动，引用路径自动更新。

### 3.5 本地迁移

- **整库拷贝**：将笔记库文件夹复制到另一台电脑，用 Spark“打开文件夹”即可使用，无需任何转换。
- **导出/导入**：
  - 导出笔记库为 `.zip`（包含笔记、附件与 `.ttnote/config/`，不含缓存/历史/回收站）。
  - 从 `.zip` 导入为新笔记库。

## 4. 界面布局

> 视觉设计以 [prototype/index.html](../prototype/index.html) 为定稿设计稿（风格 A：靛青·紧凑工具型，含浅色、纸张、护眼、夜读、纯黑五套主题），界面开发须与其一比一一致。下方线框图只示意功能区域；布局细节以设计稿为准（例如格式工具栏位于右栏顶部，而不是横跨左右两栏）。

### 4.2 标题栏（自绘，单行）

从左到右：

| 区域 | 内容 |
| --- | --- |
| 菜单按钮 `≡` | 下拉菜单：文件 / 编辑 / 视图 / 帮助 |
| 侧栏开关 | 显示/隐藏左栏 |
| 后退 / 前进 | 在笔记跳转历史中导航 |
| 标签页区 | 多标签页，可关闭、拖拽排序、中键关闭、右键（关闭其他/关闭右侧）；末尾有“+”按钮新建笔记 |
| 同步状态 | 按笔记库选择的同步方式显示状态（见 5.12）。WebDAV：已同步 / 有未上传的改动 / 云端有更新 / 有需要确认的文件 / 进行中 / 失败，点击打开菜单（上传本地改动、从云端同步、检查云端更新、同步设置）。Git：有未提交改动时显示圆点，悬停显示领先 / 落后远程的提交数，点击“一键同步”（先拉取再推送，见 5.14）。未配置同步时点击打开同步设置 |

| 设置 | 打开设置 |
| 窗口按钮 | 最小化 / 最大化 / 关闭；标题栏空白处可拖动窗口、双击最大化 |

菜单内容：

- **文件**：新建笔记、新建思维导图、新建流程图、新建文件夹、打开笔记库、切换笔记库、导入、导出笔记库、导出当前笔记（后续版本）、退出
- **编辑**：撤销、重做、剪切、复制、粘贴、查找、替换
- **视图**：显示/隐藏侧栏、显示/隐藏格式工具栏、显示/隐藏状态栏、正文自适应宽度（开关，见 4.6）、主题（浅色/纸张/护眼 | 夜读/纯黑）、放大/缩小/重置缩放
- **帮助**：命令面板、快捷键设置、关于、打开日志目录

### 4.3 格式工具栏

- 常驻于标题栏下方，默认显示，可在设置/视图菜单中隐藏整个工具栏。
- 当前标签页是思维导图或流程图时，格式工具栏换成图的工具栏（见 5.18），且不受“隐藏格式工具栏”影响。

### 4.5 文件树交互

- 无限层级文件夹，展开/折叠状态记忆。
- 顶部按钮：新建（原“新建笔记”按钮改为下拉菜单：新建笔记、新建思维导图、新建流程图、新建表格簿、AI 生成流程图…、AI 生成思维导图…、新建文件夹）、新建文件夹（保留原按钮）、全部折叠、排序方式。
- 新建位置：选中的文件夹；选中的是笔记或图时用它所在的文件夹；没有选中项时用当前笔记或图所在文件夹；都没有则为根目录。新建后命名为“未命名”（重名时加序号），并在文件树中直接进入改名状态。思维导图和流程图的新建规则相同。
- 重命名：F2、右键菜单或正文大标题；删除：Delete 键或右键菜单。
- 排序：按名称 / 修改时间 / 创建时间，升序或降序；另支持**手动拖拽自定义排序**。
  - 排序方式存在 `.ttnote/config/sort.json`，自定义顺序存在 `.ttnote/config/order.json`，都随笔记库同步；手机和笔记柜按同一种方式排列（旧版本建的笔记库第一次打开时把本机的排序方式写进去）。Git 拉取或 WebDAV 同步完成后重新读取这些配置。
  - 文件夹始终在前。名称排序：数字、字母开头的在汉字开头的前面；汉字按拼音；名称里的数字按数值比较，包括中文数字（“第二讲”在“第十讲”前面）和全角数字；以中文数字开头的名称排在其他汉字名称前面。
  - 自定义排序不分升降序。新建、移入（包括保存 AI 生成的图、把对话保存为笔记）的项排在所在文件夹的末尾；这个文件夹还没有顺序时，先按当前显示的顺序建一份。
  - 时间排序不用文件系统的时间（同步下载、Git 检出会把它改成写入时刻；保存时“先写临时文件再改名”会让 Windows 上的创建时间每次都变），而用 `.ttnote/config/times.json` 记录的时间，随笔记库同步：
    - 文件第一次出现时补记：创建时间优先用 Front Matter 的 `created`；没有时取 Git 第一次提交、最早的历史版本、文件系统创建和修改时间中最早的。修改时间：在 Git 里且没有未提交改动时用最后一次提交时间，否则用文件的修改时间。
    - 之后按内容哈希判断：内容变了（在本应用或其他编辑器里改过）才更新修改时间；同步下来的文件内容与记录一致，不算修改。同步进行期间只读不记。
    - 改名、移动时记录跟着走；删除时去掉记录；已不存在的文件的记录在下次扫描时清掉。
    - 文件夹的修改时间取其中最近修改的项，空文件夹取创建时间。时间相同时按名称升序。
    - 每条记录一行、按路径排序；两台电脑都改过时合并（创建时间取早的，修改时间取晚的），Git 合并冲突和 WebDAV 两边都改过时都自动合并，不需要用户处理。手机只读取，不写入。
- 拖拽移动文件/文件夹；移动后自动更新双向链接与附件引用路径。
- 右键菜单：新建笔记、新建思维导图、新建流程图、新建表格簿、AI 生成流程图…、AI 生成思维导图…、新建文件夹、重命名、隐藏、删除（进回收站）、收藏/取消收藏、复制路径、在资源管理器中打开；笔记上另有“用 AI 生成思维导图”（整篇笔记，见 5.18）。
- 表格簿（`.book` 文件夹，见 5.19）显示为一个不能展开的文件节点，和文件排在一起；不能把其他项拖进去，新建位置也不会落在里面。
- 当前打开的笔记或图在树中高亮并自动定位。
- 已收藏的笔记和图在树中行尾显示星标。
- 仅展示 `.md`、`.mind.mmd`、`.flow.mmd` 文件、表格簿与文件夹；隐藏 `.ttnote/` 及 `*.assets/` 附件文件夹。思维导图和流程图用各自的图标，名称不显示扩展名，行尾用小字标出“导图”“流程”。
- **隐藏文件和文件夹**：右键“隐藏”后不再显示在文件树中（文件夹连同其中内容一起隐藏）。只影响文件树：全文搜索、快速打开、双向链接补全、标签、收藏、反向链接照常列出，已有链接照常能打开，已打开的标签页不关闭。隐藏记录按笔记库保存在本机设置里，不写进笔记库、不随同步；在应用内重命名或移动时跟着更新，删除时移除（在应用外改名后会重新显示）。父文件夹与子项的隐藏状态互相独立。在“设置 → 已隐藏”中逐个恢复或全部恢复。

### 4.6 正文区

- 正文顶部用大字显示笔记标题（即文件名），可直接点击修改，回车或失去焦点即重命名文件，Esc 取消；标题下方显示标签与创建日期。
- Markdown 编辑区（见第 5 章）。
- 正文底部显示**反向链接**面板：列出所有引用当前笔记的笔记及上下文片段，可折叠。
- **正文宽度**：固定（默认 780px，可在设置中改为 560–1200px）或自适应（铺满编辑区，左右保留内边距，不设上限）；反向链接面板与正文同宽。在设置、视图菜单或命令面板“切换正文宽度（固定 / 自适应）”中切换，AI 对话页不受影响。
- **回到顶部**：笔记往下滚动超过一屏后，编辑区右下角出现圆形“回到顶部”按钮，点击平滑滚动到顶部，回到顶部后消失。
- **`Ctrl+滚轮`（macOS 为 `Cmd+滚轮`）调整正文字号**：每格 1px，范围 13–24px，自动保存；调整时编辑区中间显示约 1 秒的“字号 16px”提示。只在笔记中生效，可在设置中关闭（默认开）。

### 4.7 状态栏

高度约 24px，显示：字数与字符数（有选区时显示选区统计）、光标行列、保存状态、同步状态与最近同步时间。编辑器只有所见即所得一种模式，不显示模式切换。当前标签页是图时，字数和行列换成类型、节点数（流程图另有连线数）和缩放比例。

## 5. 功能需求

### 5.1 编辑器

- **所见即所得**（默认）：输入 Markdown 语法即时渲染（如输入 `# ` 变标题、`**文字**` 变粗体）。
- 只提供所见即所得一种编辑模式，不提供源码模式。
- 支持元素：标题、段落、粗体/斜体/删除线/高亮、行内代码、链接、图片、引用、有序/无序/任务列表、表格（可视化增删行列）、分割线、脚注。笔记正文不支持数学公式与 Mermaid 图表（2026-09-28 从需求中删除）；思维导图和流程图以独立文件提供，见 5.18。
- **代码块**（Typora 风格）：
  - 输入 ```` ``` ```` + 语言名 + 回车，或从工具栏/斜杠菜单插入，生成独立代码框。
  - 代码框内按所选语言语法高亮，颜色随主题切换。
  - 代码框右上角可选择语言（带搜索）、一键复制代码。
  - 代码框内 `Tab` 缩进、回车保持缩进，不触发 Markdown 渲染。
  - 可选显示行号（设置项）。
- 查找与替换（`Ctrl+F` / `Ctrl+H`），支持大小写与正则。
- 格式快捷键见 4.3 工具清单，可自定义（见 5.13）。

### 5.2 自动保存

- 停止输入约 1 秒后自动写入磁盘；`Ctrl+S` 立即保存。
- 切换笔记、关闭标签页、退出应用前确保保存完成。
- 写入采用“写临时文件 → 原子替换”，避免断电导致文件损坏。

### 5.3 双向链接

- 输入 `[[` 弹出笔记名补全，生成 `[[笔记名]]` 链接；支持 `[[笔记名|显示文字]]` 与 `[[笔记名#标题]]`。
- 补全列表：继续输入按名称或路径过滤；列表可滚动，最多 200 条，标题匹配超出时底部提示“继续输入以缩小范围”；键盘上下选择时列表自动滚到选中行。输入至少 2 个字并停顿约 150 毫秒后，用全文索引搜索正文，在标题匹配之后的“正文匹配”分组中列出（最多 50 条，只含笔记，不重复标题匹配中的笔记），每条下方显示命中片段。不支持拼音匹配。
- 同名笔记：只写笔记名时优先解析到同一文件夹的笔记，其次路径最短的；补全时遇到重名笔记自动写成带路径的形式，如 `[[工作/周报]]`。
- 链接到思维导图和流程图时写上类型后缀：`[[项目上线流程.flow]]`、`[[Rust 学习路线.mind]]`（也可带路径，如 `[[工作/项目上线流程.flow]]`）；显示时隐藏后缀，并带类型图标。补全列表同时列出笔记和图，选中图时自动带上后缀。不带后缀的 `[[名称]]` 只解析到笔记，因此笔记和图同名时不会链错。链接到图不支持 `#标题`。
- `Ctrl+点击` 或直接点击（所见即所得模式下）跳转；目标不存在时提示是否创建（带后缀时创建对应类型的图）。
- 笔记或图重命名/移动时，自动更新所有引用它的链接。
- 正文底部显示反向链接（见 4.6）。

### 5.4 全文搜索

- 搜索范围：标题（文件名）、正文、标签；思维导图和流程图的文件名、节点文字、连线文字（不含 Mermaid 语法本身）。无法显示的图（见 5.18）只匹配文件名。
- 图的搜索结果标明类型，命中片段写成“节点：部署预发”“连线：测试通过？ → 部署预发”；点击打开图并选中命中的节点。`#标签` 过滤时不含图。
- 基于 SQLite FTS5 本地索引，中文按相邻两字切分（二元切分），**两个汉字的词也能命中**，任意连续文字都能搜到（偶尔会命中跨词的结果）。
- 搜索语法：空格分隔的词都要出现；`#标签` 按标签过滤（含子标签）；`path:文件夹` 按文件夹过滤。
- 结果显示笔记名、路径、命中片段（关键词高亮），点击打开并定位到命中处。
- 支持按标签、文件夹过滤。
- 索引增量更新；索引损坏或丢失时自动重建。
- 监听磁盘文件变化（外部编辑器修改、同步拉取），自动更新索引与界面。

### 5.5 标签

- 来源：Front Matter `tags` 与正文 `#标签`。
- 左栏标签视图展示全部标签及数量；支持层级标签 `#工作/周报`（按 `/` 分层展示）。

### 5.6 收藏

- 笔记与文件夹均可收藏，收藏列表在左栏“收藏”视图，可拖拽排序。
- 收藏数据存于 `.ttnote/config/`，随同步。

### 5.7 多标签页

- 同时打开多篇笔记，每个标签页独立保留滚动位置与撤销历史。
- 思维导图和流程图也在标签页中打开，标签上用图标区分类型；预览标签页、固定、恢复的规则与笔记相同，每个标签页独立保留画布位置、缩放与撤销历史。
- 单击文件树为“预览标签页”（斜体标题，再次单击其他笔记会替换它），编辑或双击后固定。
- 重启应用后恢复上次打开的标签页。

### 5.8 历史版本

- 保存时对笔记和图做本地快照，存于 `.ttnote/history/`，**不同步**。
- 图的历史版本：预览时把该版本画成只读的图，可恢复；不提供按行对比（界面不显示 Mermaid 文本，见 5.18）。
- 节流：同一篇笔记 5 分钟内最多保留一份快照。
- 默认保留 30 天，可在设置中调整。
- 查看某笔记的历史版本列表（文件菜单或命令「历史版本」），预览任一版本、按行与当前已保存内容对比、恢复到该版本（恢复前当前内容也会存为一份快照）。保留天数在设置中调整，0 表示不自动清理。

### 5.9 回收站

- 删除前弹出确认框；确认后笔记/图/文件夹（含附件）移入 `.ttnote/trash/<时间戳>/`，保留原相对路径并记录原位置，**不同步**。
- 可查看、恢复到原位置、彻底删除、清空回收站。
- 默认保留 30 天后自动清理，可在设置中调整。

### 5.10 命令面板与快速打开

- `Ctrl+P`：快速打开，按笔记名和图的名称模糊搜索（字符按顺序出现即命中，连续命中排在前面），图带类型图标；未输入时列出最近打开的笔记和图；输入 `>` 切换到命令面板。
- `Ctrl+Shift+P`：命令面板，可执行所有命令，显示分类与当前快捷键；未输入时先列出最近使用的 5 条命令（应用级设置）。

### 5.11 主题

- 五套内置主题，分为两组：
  - 浅色系：**浅色**（冷灰 + 靛青）、**纸张**（米黄底 + 赭红强调）、**护眼**（浅豆沙绿底 + 墨绿强调）
  - 深色系：**夜读**（深蓝灰 + 琥珀强调）、**纯黑**（接近纯黑的底色，强调色沿用夜读的琥珀色）
- 各主题的布局、字体、尺寸完全相同，只替换配色；代码高亮、成功 / 危险等状态色同步切换，见设计稿。
- 正文元素配色：常用元素各有固定色系，五套主题里色系不变，只调深浅以保证对比度。笔记正文、AI 待确认区域、AI 对话回复使用同一套配色，不提供关闭开关。
  - 双向链接、列表圆点与序号：主题强调色
  - 外部链接：青色
  - 行内代码：玫红文字 + 同色淡底，无边框
  - 引用块：蓝色左竖线 + 同色淡底，右侧圆角
  - 任务列表：未勾选为淡绿边框；已勾选为绿色实心框，已完成项文字变灰并加删除线
  - 标签（Front Matter 标签与行内 `#标签`）：紫色文字 + 同色淡底
- 不提供“跟随系统”，不支持自定义主题。
- 切换方式：
  - 标题栏右侧的月亮/太阳按钮：分别记住上次使用的浅色系主题和深色系主题，点击在两者之间切换。当前为深色系时显示太阳，浅色系时显示月亮；按钮提示写明要切换到的主题，如“切换到纯黑”。首次使用时分别为浅色和夜读。
  - 视图菜单“主题”：列出五套主题，两组之间用分隔线隔开，当前主题打勾。
  - 设置 → 外观：单选列表，每项前有色块，显示该主题的标题栏底色、正文底色和强调色。
  - 命令面板：“切换深浅主题”（即标题栏按钮的操作），以及“主题：浅色”“主题：纸张”等直接选择某套主题的命令；均默认无快捷键，可自定义。
  - 从任何入口选中一套主题，都会更新它所在分组“上次使用”的记录。
- 选择结果存为应用级设置（每台电脑各自一份，不随笔记库同步）；启动时在窗口显示前应用主题，不出现闪白。

### 5.12 同步（WebDAV）

> 每个笔记库在“不同步 / WebDAV / Git（见 5.14）”中选一种同步方式，不能同时开启。

#### 配置

- 按笔记库分别配置：WebDAV 地址、用户名、密码、远端目录。
- 密码存入系统凭据库，不写入任何配置文件。
- “测试连接”在按钮旁直接显示结果，例如“连接成功，云端目录里有 36 篇笔记”；远端目录不存在时说明第一次上传会自动创建。
- 保存后读一次云端列表，第一次使用时给出建议：云端为空建议“上传”，本地为空建议“从云端同步”，两边都有时让用户选以哪边为准。
- 兼容坚果云、Nextcloud、群晖 NAS、Alist 等常见 WebDAV 服务；不支持 `Depth: infinity` 的服务逐层读取目录，任何一层读取失败都中止，不能当成空目录。

#### 同步范围

- 同步：笔记、思维导图与流程图（`.mind.mmd`、`.flow.mmd`，同步规则与笔记相同）、表格簿里记录表顺序的 `.book.json`（见 5.19）、附件、`.ttnote/config/`。
- 不同步：`.ttnote/cache/`、`history/`、`trash/`、`sync/`，以及云端回收文件夹 `.spark-trash/`。
- 同步的对象是笔记库：没有打开笔记库时，标题栏同步图标照常可点，点击（或在命令面板执行“立即同步”“一键同步”）时提示“需要先新建或打开一个笔记库才能同步”，并打开笔记库对话框；设置页“同步”里也显示这句提示。Git 同步相同。

#### 原则与触发方式

- **云端是正本**，本地是工作副本。两个手动操作，从标题栏同步图标的菜单进入（菜单里同时显示上次同步时间和各自的待处理数）：
  - **上传本地改动**：本地 → 云端。
  - **从云端同步**：云端 → 本地，以云端为准。
- 默认只在用户点击时执行。设置里有两个开关：
  - “打开笔记库时检查云端更新”（默认开）：只读取云端文件列表，不下载，有更新时图标提示；
  - “停止编辑 1 分钟后自动上传”（默认关）：只处理不需要确认的新增和修改，需要确认的留在菜单里等用户处理。
- 程序永远不会自动改动本地文件。
- 从旧版升级时，原来的双向自动同步一律改成手动（自动上传关闭），并用浮动提示说明一次。

#### 同步机制

- 本地记录上次同步时各文件的状态（哈希、修改时间、远端 ETag），与本地、远端当前状态比较，判断每个文件在两边各自有没有变。只传输有变化的文件。
- **上传**：本地新增或修改的文件传到云端。云端那份也被别的电脑改过时，覆盖前把云端旧版本移到云端回收文件夹；本地删掉的文件，云端移到云端回收文件夹。本地删了但云端被改过的，保留云端版本。
- **从云端同步**：云端新增或修改的文件下载到本地；本地改过的笔记被覆盖前存一份历史版本（附件移进回收站）；云端删掉的文件，本地移进回收站；本地新建、还没上传的文件保留不动并提示。
- **执行前的清单**：本次操作会覆盖或删除文件时，先弹出清单（按“覆盖、移除、新增、更新、保留”分组，可逐个取消勾选），确认后才执行；只新增和更新时直接执行。执行前重新读取两边，清单之外的覆盖和删除一律跳过。
- **云端回收文件夹**：`.spark-trash/<日期>/<时分秒>/<原路径>`，超过回收站保留天数（见 5.9）的日期目录在上传时删除；保留天数为 0 时不清理。
- **防丢数据**：上次同步时云端有文件、这次读到空的，或上次有 10 个以上文件、这次少了一半以上时，判定云端目录异常，停止执行并提示检查地址和目录；用户勾选“我确认云端就是这样，继续”后才执行。
- 执行过程中用户又保存了某个文件时，这个文件本次跳过，下次再按最新状态判断。
- 文件时间记录 `.ttnote/config/times.json` 两边都改过时不列入清单，上传和同步时都把两份合并（见 4.5）；只有本地改过时，“从云端同步”不用云端旧版覆盖它。
- 所有失败（网络中断、认证失败等）都明确提示原因，不静默失败。
- 当前不加密。

### 5.13 快捷键

#### 范围

- **所有命令**均可自定义快捷键：格式工具（见 4.3）与下表中的应用命令，以及命令面板中的全部命令。

- macOS 上 `Ctrl` 自动映射为 `Cmd`。

| 新建思维导图 / 新建流程图 / 新建表格簿 | 无 |

| 命令面板 | `Ctrl+Shift+P` |
| 全文搜索 | `Ctrl+Shift+F` |
| 显示/隐藏侧栏 | `Ctrl+Shift+B` |
| 设置 | `Ctrl+,` |
| 放大 / 缩小 | `Ctrl+=` / `Ctrl+-` |
| 重置缩放 | 无 |
| 立即同步 | 无 |

#### 自定义规则

- 在“快捷键设置”中列出全部命令（帮助菜单或命令面板打开弹窗；设置页中是同一份），按分类分组，显示作用范围（全局 / 编辑器），支持按名称或快捷键搜索。
- 点击某条命令后直接按下组合键即可录入（Esc 取消，Backspace 设为“无”）；可单条或全部恢复默认；录入期间全局快捷键暂停。
- 快捷键必须包含 `Ctrl` 或 `Alt`（只带 `Shift` 会与正常输入冲突），`F1`–`F12` 与 `Tab` / `Shift+Tab` 除外。按物理键位识别，`Shift` 不改变按键名（如 `Ctrl+Shift+,`）。
- 保留组合键不可占用：`Ctrl+C`、`Ctrl+X`、`Ctrl+V`、`Ctrl+A`、`Alt+F4`。
- **冲突处理**：录入的组合键已被其他命令占用时，提示“已被 xxx 占用，是否覆盖？”；确认后原命令的快捷键变为“无”。
- **存储**：应用级设置（每台电脑各自一份），不随笔记库同步；支持导出/导入 JSON 文件（`{"app":"Spark","version":1,"keybindings":{命令 id: 快捷键或 null}}`）。导入时跳过未知命令和无效组合键并列出原因；文件内有两个命令使用同一组合键时拒绝导入。

### 5.14 Git 版本控制

#### 定位与实现

- 本地提交随时可用，用于留存历史、回退；配置远程仓库后可拉取和推送，作为同步方式之一（见 5.12，与 WebDAV 二选一）。
- 调用系统已安装的 `git` 命令，沿用用户现有的 Git 配置和 SSH 密钥。HTTPS 远程可以在软件里填写账号和密码（或访问令牌），只保存在系统凭据库里；没有填写时沿用系统凭据管理器里已有的账号，但不让它弹出自己的登录窗口。
- 与历史版本（5.8）相互独立：本地快照兜住两次提交之间的编辑，Git 记录有意义的里程碑。

#### 仓库

- 整个笔记库文件夹即一个仓库。`.ttnote/cache/`、`.ttnote/history/`、`.ttnote/trash/`、`.ttnote/sync/` 自动写入 `.gitignore`；`.ttnote/config/`（收藏、排序方式与自定义顺序、文件时间记录等）要提交。
- 笔记库已经是 Git 仓库时直接沿用，只在 `.gitignore` 中补上缺少的规则。不是仓库时，用户在同步设置里选了 Git 并点“连接”，或在版本控制视图点“初始化仓库”，才执行 `git init`。
- 只在当前分支上工作，不提供切换 / 新建分支界面。处于分离 HEAD、正在合并或变基时，禁用提交、拉取、推送并提示原因。

#### 提交

- 默认手动：填写提交说明后点击“提交”（`Ctrl+Enter`），提交全部改动（相当于 `git add -A`）。
- 可在设置中开启自动提交：停止编辑 5 分钟（可调）后提交一次；退出软件时如有未提交改动也提交一次。
- 自动提交的说明自动生成，形如 `自动提交：修改 3 篇（周报、读书笔记、WebDAV 同步设计）`，最多列出 3 个笔记名，超出用“等”；新增、删除同样写明。思维导图和流程图与笔记一起计数，名称不带扩展名。自动提交属于后台操作，不调用 AI。
- 手动提交时可以点提交说明下方的“AI 生成说明”，由 AI 根据改动写说明（见 5.16）。
- 提交身份不需要用户填写：已有全局 Git 配置时直接用；没有时自动生成并只写入本仓库（`git config --local`）。用户名取远程账号，没有账号时取系统用户名；邮箱用不会收信的地址（GitHub 为 `账号@users.noreply.github.com`，其他为 `账号@users.noreply.<域名>`）。可在 Git 设置的“高级”里修改。

#### 拉取与推送

- 只支持手动，不提供自动拉取 / 推送。操作均通过按钮完成，无需输入命令：
  - 标题栏同步图标：一键同步（先拉取再推送），悬停显示领先 / 落后远程的提交数；
  - 版本控制视图顶部：单独的“拉取”“推送”按钮。
- 拉取（含一键同步）前若有未提交的改动，或已提交但还没推送的提交里删掉了远程仍有的文件，先列出这些改动（按删除、修改、新建、未推送的删除分组），让用户选择：
  - **以仓库为准**：放弃本地改动，包括还没推送的提交，和远程仓库保持一致。删掉的恢复回来，改过的笔记恢复成远程版本（当前内容先存为历史版本），远程没有的文件和改过的附件移进回收站；然后拉取。
  - **保留本地改动并合并**：先自动提交一次（说明为 `拉取前自动提交：……`），再拉取合并。本地删除的笔记推送后在仓库里也会被删除。
  - 取消。
  不再静默自动提交：本地误删的笔记被自动提交后，拉取无法把它恢复回来，推送后远程也会被删除。
- 首次拉取时远程是空仓库或还没有当前分支，跳过拉取；远程只有网页上建仓库时生成的提交（如 README）时，允许合并无共同历史的分支。
- 首次推送时远程没有对应分支，自动执行 `git push -u origin <当前分支>`。
- **连接远程仓库**（设置页“同步 → Git”和「Git 设置」弹窗用同一套流程）：
  1. 填写远程地址，点“连接”：需要时初始化仓库，设置 origin，实际访问一次远程（`git ls-remote`）；
  2. HTTPS 仓库要求登录时，就地显示“账号”和“访问令牌”，认得 GitHub、Gitee、GitLab 时给出“去创建访问令牌”的链接；填写后点“登录并连接”再次验证；
  3. 连接成功后说明远程的情况并给出第一步按钮：远程为空时“推送本地笔记”，远程有笔记、本地没有提交时“拉取远程笔记”，两边都有时“开始同步”（先拉取再推送）；
  4. 本地分支还没关联远程、远程也没有同名分支时，把本地分支改成远程默认分支的名字（如 `master` 改成 `main`），避免拉不到远程的笔记。
- **登录失效**：拉取 / 推送时远程要求登录或拒绝了已保存的账号，弹窗填写，保存后自动重试刚才的操作。
- **冲突**：笔记文件冲突时与 WebDAV 规则一致，两份都保留（远程版本为原文件，本地版本另存为 `笔记名 (冲突 电脑名 日期).md`），自动完成合并提交并提示用户手动合并；思维导图和流程图按笔记处理，副本保留类型后缀，如 `项目上线流程 (冲突 电脑名 日期).flow.mmd`；`.ttnote/config/` 里的配置冲突时不打扰用户：文件时间记录 `times.json` 两边合并，其余（排序、收藏等）以正在同步的这一台为准；其他文件（图片等）冲突时中止合并，提示用外部 Git 工具处理。
- 远程仓库地址在设置页“同步 → Git”和「Git 设置」弹窗里填写（相当于 `git remote add origin`，也显示已有的远程仓库）。弹窗从版本控制视图、命令面板，以及尚未配置远程时点击标题栏同步图标打开，和设置页是同一套流程。自动提交的开关和等待时长存在 `.ttnote/config/git.json`。
- 所有 Git 失败（未安装、认证失败、网络错误等）都明确提示原因。所有操作结果用窗口右上角的浮动提示显示（成功的几秒后消失，失败的保留到手动关闭），设置窗口里的测试、保存、连接结果直接显示在按钮附近。未检测到 Git 时，版本控制视图提示安装并给出下载链接，其他功能不受影响。

#### 当前不做

- 勾选部分文件提交、查看差异（与历史版本的对比界面一起在后续实现）、分支管理、Git LFS。

### 5.15 一键整理（规则版）

- 按固定规则整理当前笔记的文字格式，**不联网、不调用 AI**，结果可预测。
- 入口：格式工具栏“一键整理”按钮、命令面板，默认快捷键 `Ctrl+Shift+L`（可自定义）。
- 范围：有选中文字时只整理选中部分，否则整理整篇。代码块、行内代码、链接地址、Front Matter 一律不改。
- 整理结果算一步操作，`Ctrl+Z` 一次撤销。完成后在状态栏提示改了多少处（按规则分类计数）；没有需要整理的地方时提示“没有需要整理的地方”。
- 规则（设置 → 编辑器中每条单独开关）：

| 规则 | 默认 |
| --- | --- |
| 中文与英文、数字之间加空格 | 开 |
| 中文句子里的半角标点改为全角（`,` → `，`） | 开 |
| 全角英文和数字改为半角（`ＡＢＣ１２３` → `ABC123`） | 开 |
| 合并连续的空行 | 开 |
| 去掉行尾空格 | 开 |
| 修正标题跳级（H1 下面直接是 H3 时改为 H2） | 关（会改变结构） |

- 规则细节：
  - 中英文空格：行内代码整体按英文处理（与中文之间也加空格），代码内部不动；双向链接、图片前后不加空格。
  - 中文标点：只转换 `,` `;` `:` `?` `!` `.` 六种，且前一个字符必须是中文（或双向链接后紧跟中文）；`.` 还要求后面是结尾、空白或中文，因此 `1.0`、`readme.md`、`...` 不受影响；转换后去掉标点前后多余的空格。括号不转换。
  - 空行：同一层级里连续的空段落只保留一个。
- Markdown 语法层面的统一（列表符号、强调符号等）由编辑器保存时完成，不属于本功能。
- 实现：在编辑器的文档结构上逐个文本片段应用规则，加粗、链接等格式原样保留；排版规则见第 2 章。

### 5.16 AI 功能

#### 原则

- **只在用户主动点击时发送内容**，后台不自动发送任何笔记；需要后台运行的功能（如自动提交）不调用 AI。
- 每次发送前在界面上说明发送了什么（如“附带当前笔记，约 1,286 字”）。
- 所有 AI 请求都可以随时取消，取消后不写入任何内容。

#### 配置（设置 → AI）

- 只支持 **OpenAI 兼容接口**（Claude、Gemini 用各自官方的兼容地址）。
- **模型列表**：设置页右上角“添加模型”，列表每行显示名称（带“默认”标记）、服务商、模型名、上下文长度及来源，以及“编辑”“删除”（删除前确认）。列表上方是“默认模型”下拉：AI 指令、总结、整理结构、提交说明、生成思维导图、整理和生成流程图都用默认模型；AI 对话里可以临时切换为列表中的任一模型（见 5.17）。删掉默认模型时改用列表第一个。还没有模型时显示“还没有添加模型 / 添加第一个模型”。
- **添加 / 编辑模型**（同一个对话框）：
  - 服务商：下拉选择预设，选中后填好接口地址，并把模型下拉换成该服务商的预设模型（显示名称同时填好）。
  - 接口地址：可修改；“自定义”时自己填写。
  - API Key：**按接口地址保存**，同一地址的多个模型共用；这个地址已保存过时显示“已保存（与同一接口地址的其他模型共用）”和“修改”，否则显示输入框。本机服务（Ollama、LM Studio）可以不填。
  - 模型：可从下拉选择，也可以直接输入；“从服务商读取”调用模型列表接口，读到的模型并入下拉，给出了上下文长度的一并记下。
  - 显示名称（可选，不填时显示模型名）、上下文长度（可选，留空为自动，提示里显示自动得出的值和来源）。
  - “测试连接”：用这个模型发一条很短的请求（Key 还没保存时用输入框里的），显示成功或具体失败原因。
  - 保存前校验：接口地址以 http(s):// 开头、模型名不为空、同一接口地址下不能重复添加同一模型。改了接口地址或删除模型后，原地址已没有模型使用时一并清除它的 Key。
- **预设服务商与模型**（2026-10 按各家官方文档；模型名会变，所以总能手动输入）：OpenAI（GPT-6 Astra、GPT-6.1 Sol、GPT-6 Luna）、Anthropic Claude（Opus 5.5、Sonnet 5.5、Haiku 4.5、Fable 5.1）、Google Gemini（3.1 Pro、3.8 Flash、3.5 Flash-Lite）、Mistral（Large 4、Medium 3.5）、DeepSeek（V4 Pro、V4.1 Flash）、通义千问（Qwen3.8 Max、Qwen3.7 Plus、Qwen3.8 Flash）、Kimi（K3、K2.7 Code、K2.6）、智谱 GLM（GLM-5.3、GLM-5.3-Flash、GLM-4.7-Flash）、豆包（Seed 2.1 Pro / Turbo、Seed 2.0 Lite，模型名以方舟控制台为准）、文心（ERNIE 5.1、5.0、4.5 Turbo 128K）、腾讯混元（Hy4 Preview、Hy3，接口地址为 TokenHub）、MiniMax（M3、M2.7、M2.7 极速版）、阶跃星辰（Step 5 Preview、3.7 Flash、3.5 Flash）；硅基流动、OpenRouter、Ollama（本机）、LM Studio（本机）不预设模型，用“从服务商读取”；以及“自定义”。xAI Grok 当前只提供 Responses 接口，不预设。
- 每个模型有一个**上下文长度**（tokens），按以下优先级确定：手动填写 > 服务商模型列表接口返回的值 > 内置的常见模型表 > 默认 128K。
- API Key 存入系统凭据库，不写入任何配置文件。模型列表和默认模型存为应用级设置。
- 从旧版本升级：原来的一套接口地址和模型列表自动转成列表里的各项（按接口地址认出服务商，认不出时为“自定义”），原来排第一的成为默认模型；原来唯一的 API Key 搬到那个接口地址名下。
- 不提供温度等高级参数，不允许修改提示词（后续有需要再加）。
- 还没有添加模型时点任何 AI 功能，先提示“尚未配置 AI”并提供“去添加模型”。

#### 调用与失败处理

- 请求从 Rust 侧发出，流式返回，界面逐字显示。
- 网络错误、限流（HTTP 429）自动重试 1 次；认证失败、余额不足、超出上下文长度等直接显示具体原因，并提供“重试”。
- 60 秒内没有收到任何内容算超时。
- **长度上限按所用模型的上下文长度计算**：可发送的 token 数 = 上下文长度 − 给回复预留的部分（8K 与上下文长度的 10% 取较小者）。token 数在本地估算（中文约 1 字 1 token，其他文字约 4 个字符 1 token），界面上标“约”。超过上限时：AI 指令、总结、整理结构、生成思维导图直接提示“笔记过长”，生成流程图提示“描述过长”；生成提交说明时每个文件只保留开头部分的差异。
- **每次请求的上下文相互独立**：AI 指令、总结、整理结构、提交说明、生成思维导图、整理和生成流程图每次只发送本次需要的内容，不带任何历史；AI 对话的每个会话只带本会话自己的消息，不同会话、不同功能之间互不共享。
- 日志中不记录 API Key 和发送的笔记内容。

#### 功能清单

| 功能 | 入口 | 发送内容 | 结果处理 |
| --- | --- | --- | --- |
| AI 指令 | 斜杠菜单“AI 指令” | 用户输入的指令；默认附带当前笔记全文，可取消勾选只发送指令 | 在光标处插入**待确认区域**，回答逐字流入，可停止；完成后“接受 / 放弃 / 重新生成”。接受算一步操作，可撤销；放弃不留痕迹 |
| 总结当前笔记 | 工具栏 AI 下拉、命令面板 | 当前笔记全文 | 弹窗显示，可“复制”或“插入到笔记开头”（插成引用块），可重新生成 |
| AI 整理结构 | 工具栏 AI 下拉、命令面板 | 当前笔记全文 | 见下文 |
| 生成提交说明 | 版本控制视图“AI 生成说明” | 本次改动的差异；改动过大时只发文件列表和每个文件的部分差异，并在界面说明 | 填进提交说明输入框，可再修改 |
| 生成思维导图 | 整篇笔记：文件树中笔记的右键菜单、命令面板；按描述：“新建”下拉、文件树右键菜单、笔记选中文字的右键菜单、命令面板、空白思维导图的提示 | 当前笔记全文，或用户写的描述 | 逐步画出思维导图，结束后“保留 / 丢弃”，保留才写文件，见 5.18 |
| 生成流程图 | “新建”下拉、文件夹右键菜单、笔记选中文字的右键菜单、命令面板、空白流程图的提示 | 用户写的描述和选的方向；按意见修改时另发当前这一版流程图和意见 | 逐步画出流程图，结束后可提修改意见、回到上一版，“保留 / 丢弃”，保留才写文件，见 5.18 |

“总结当前笔记”“AI 整理结构”“AI：把当前笔记生成思维导图”“AI：生成思维导图”“AI：生成流程图”也注册为命令，默认无快捷键，可自定义。

#### AI 整理结构

- 只调整结构（标题层级、分段、列表化），不增删观点；Front Matter、双向链接、图片与附件引用、代码块不允许改动。
- 生成后打开**左右对比**弹窗（左原文、右整理后，差异高亮），确认后才替换。
- 程序自动核对上述不可改动的内容数量与原文是否一致：一致时显示“核对通过”；不一致时标红说明缺了什么，“替换”不可用，只能重新生成或放弃。
- 替换前存一份历史快照（5.8），替换算一步操作，可撤销。
- 笔记超过单次请求的长度上限时直接提示“笔记过长”，不分段处理。

### 5.17 AI 对话

> 2026-09-28：取消原“书籍课程”需求，改为类似 ChatGPT 的对话界面。

#### 入口与布局

- 左栏最底部固定一行“AI 对话”。点击后左栏切换为**会话列表**，右侧编辑区打开“AI 对话”标签页；点左栏顶部其他视图图标或切到笔记标签页即回到笔记。
- 会话列表：顶部“新对话”按钮；会话按“今天 / 昨天 / 更早”分组，最新的在前；每个会话右侧“更多”菜单：重命名、删除（删除前确认）。新会话用第一条消息自动命名。
- 对话标签页：顶部是会话标题；中间是消息列表；底部是输入框，输入框右下角发送按钮左侧是模型切换下拉（列表来自设置里的模型，显示名称、服务商和上下文长度，只影响当前会话；会话记住所选模型，模型被删掉后改用默认模型），输入框下方是上下文用量。
- 未配置 AI 时点“AI 对话”，先提示“尚未配置 AI”（同 5.16）。

#### 发送

- 输入框：Enter 发送，Shift+Enter 换行；生成中发送按钮变为“停止”。
- 附件（每条消息可以有多个，发送前可以移除）：
  - **图片**：png、jpg、webp、gif，可粘贴、拖入或点回形针按钮选择；以 OpenAI 兼容格式（base64 图片）发送，需要模型支持识图。
  - **文本类文件**：txt、md、csv、json 与常见代码文件，读取内容后作为文字附在消息里。
  - **引用笔记**：输入 `@` 按笔记名模糊搜索，回车引用，发送时附上笔记正文。
  - 不支持 PDF、Word（后续版本）。
- 单个文本附件上限 1 MB、单张图片上限 10 MB，超过时提示，不添加。
- 只在用户点击发送时发送；发送的内容就是用户看到的消息和附件。

#### 回复

- 流式显示，按 Markdown 渲染（标题、列表、表格、行内代码、代码块高亮），不执行 HTML。
- 切换到别的会话或新建会话不停止正在生成的回复，生成在后台继续，完成后自动保存；回到该会话能看到已生成的内容，会话列表里标为“生成中”。删除正在生成的会话才会停止它。只有当前打开的会话显示“停止”按钮。
- 每条回复下方：复制、插入到笔记（插到最近编辑的笔记的光标处；没有打开的笔记时不可用）、保存为新笔记（在文件树当前文件夹新建，标题取回复第一行）。最后一条回复还有“重新生成”，并显示所用的模型名。
- 请求失败时，在回复位置显示原因并提供“重新生成”；消息带图片且失败时，额外提示“当前模型可能不支持图片，可以切换到支持识图的模型”。
- 当前不做：编辑历史消息后分叉、搜索会话、联网搜索、语音、生成图片。

#### 上下文

- 每个会话都是独立的上下文，只带本会话的消息；新建会话即从空白上下文开始。
- 每次请求带上系统提示词和本会话从最近往前的历史消息，总量不超过**当前所选模型**的可发送上限（计算方式见 5.16）；更早的消息不发送，并在消息列表中显示分隔线“更早的 N 条消息未发送给 AI”。切换模型后上限随之变化。
- 输入框下方显示上下文用量进度：“上下文 约 12.3K / 131K tokens”（分母是当前模型的上下文长度），包含本次待发送的内容；到达可发送上限时进度条变色并注明“更早的消息不再发送”。图片不计入估算。

#### 存储

- 会话保存在本机应用数据目录（每个会话一个 JSON 文件，图片另存为文件），**不随笔记库同步**，不进入笔记库和搜索索引。
- 删除会话会删除其消息与图片；已插入或保存到笔记的内容不受影响。
- 日志中不记录对话内容。

### 5.18 思维导图与流程图

> 2026-09-29 新增。2026-09-28 删除的是写在笔记正文里的 Mermaid 代码块；本节的图是和笔记放在一起的独立文件，笔记正文仍不支持 Mermaid（见 5.1）。

#### 文件

- 两种文件，可放在笔记库的任意文件夹里：
  - 思维导图：`名称.mind.mmd`，内容为 Mermaid `mindmap` 语法；
  - 流程图：`名称.flow.mmd`，内容为 Mermaid `flowchart` 语法。
- 文件是 UTF-8 纯文本，Git 中能按行看出改动。只保证 Spark 自己能正确显示；其他 Mermaid 工具也许能打开，但看不到结构、配色、样式和概要，显示效果不做保证。
- 类型只看扩展名。文件树、标签页、链接补全、搜索结果中显示名称时去掉 `.mind.mmd` / `.flow.mmd`。
- 图没有 Front Matter、标签和附件目录。
- 支持的语法（其余写法一律视为不支持，见“无法显示”）：
  - 思维导图：按缩进表示层级的纯文字节点，第一个节点为根节点；`%%` 注释。节点文字含半角括号等特殊字符时，Spark 写成 `["文字"]`，读回时仍是纯文字节点，输入什么就显示什么。
  - 流程图：方向 `TD`（`TB`）、`BT`、`LR`、`RL`；节点形状九种：矩形 `id[文字]`、圆角 `id(文字)`、胶囊 `id([文字])`、圆 `id((文字))`、菱形 `id{文字}`、六边形 `id{{文字}}`、平行四边形 `id[/文字/]`、梯形 `id[/文字\]`、圆柱 `id[(文字)]`；连线：`-->`（实线箭头）、`---`（无箭头）、`-.->`（虚线）、`==>`（粗线），连线文字 `-->|文字|`；`%%` 注释。
  - 不支持的例子：子图 `subgraph`、`style`、`classDef`、`click`、思维导图的其他节点形状与图标、其他 Mermaid 图表类型。
- Spark 的扩展信息写成以 `%% spark:` 开头的注释，随文件同步和进入 Git：
  - 整张图：结构、节点外观和线条（思维导图）、配色方案、主题间距，写在 `mindmap` / `flowchart` 下面的第一行；
  - 节点样式：写在该节点的前一行；流程图节点的位置、是否是文字也写在这一行；
  - 概要：写在概要节点的前一行，记录它概括的同级节点范围；
  - 流程图节点手动调整的大小也写在节点的前一行；
  - 流程图连线的走线（直角 / 圆角 / 直线）、两端接在哪一边和手动拖过的中间段位置：写在该连线的前一行。
  - 这些注释和节点对不上时（例如在外部大幅改动过），忽略对不上的部分，节点本身照常显示。
- 保存：按固定格式重新生成整个文件；节点编号和定义顺序保持不变，普通 `%%` 注释保留在原来的位置。在 Spark 中新建的文件每次保存格式一致；在外部写的文件第一次保存时格式会统一一次，之后保持稳定。
- 写入同样采用原子替换（5.2）；只打开不编辑不会写回文件。
- 折叠状态、画布位置、缩放、样式面板是否展开等视图状态存在本机应用设置里，不写进文件，也不随笔记库同步。

#### 配色与样式

- 配色方案：默认“跟随应用主题”（颜色取自当前主题，5.11）；另有 6～8 套预设。每套预设都有浅色版和深色版，应用处于夜读、纯黑时自动用深色版。配色方案写进文件。
- 节点样式：背景色、边框色、文字颜色、字号（小 / 中 / 大 / 特大）、加粗。颜色从 12 色的色板中选，深色主题下自动调暗；另有“更多颜色”取色器，取色器选的颜色在任何主题下都原样显示。节点样式优先于配色方案；“恢复默认样式”清除节点样式。
- 主题间距：紧凑 / 标准 / 宽松，调整节点之间的距离（流程图只影响“AI 整理”和首次打开时的自动排版）。
- 节点外观（思维导图，整张图一种，写进文件）：方框（默认，根节点和一级主题画框，二级及以下是带下划线的文字）/ 纯文字（所有节点都只显示文字，不画框和下划线，连线接到文字左右两端的中间）。纯文字外观下设了背景色或边框色的节点仍画框；鱼骨图的小骨仍带下划线。
- 线条（思维导图，整张图一种，写进文件）：曲线（默认）、圆角折线、直角折线、从分叉点出发的斜线、从父节点直接出发的直线、先斜后平的折线。鱼骨图的大骨、小骨不受影响。
- 导出（见“导出”）按当前显示的配色出图。

#### 新建

- 入口：文件树“新建”下拉菜单、文件树右键菜单、文件菜单、命令面板“新建思维导图”“新建流程图”（默认无快捷键，可自定义）。标签栏的“+”和 `Ctrl+N` 仍然只新建笔记。

- 只在图上编辑，界面上不显示 Mermaid 文本，不提供文本编辑。
- 结构（整张图一种，写进文件）：向右（默认）、左右平衡、向左、向下（组织结构图）、鱼骨图。

- 点空白处取消选中；没有选中节点时，直接打字、`Tab`、`Enter` 不起作用。
- 拖动节点放到另一个节点上，改为它的子节点；放到两个同级节点之间，调整顺序。选中多个节点时一起拖动（保持原来的先后顺序）。拖动时在将要放入的位置显示一个虚线框的预览节点。
- 展开 / 折叠：工具栏“折叠”下拉：折叠 / 展开所选、全部展开、全部折叠、展开到第 1 / 2 / 3 / 4 层。
- 移动画布：按住空格拖动，或按住鼠标中键拖动；滚轮上下滚动、`Shift+滚轮` 左右滚动。图比窗口小时也能拖动。
- 折叠的节点显示隐藏的子节点数量。
- 概要：选中一个或几个相邻的同级节点，点工具栏“概要”或按 `Ctrl+]`，右侧出现括号和概要节点。
  - 概要节点和普通节点一样可以改字、加子节点、改样式、折叠。
  - 范围建好后不能调整，要改就删掉重建。
  - 被概要的节点删除或移走时范围自动缩小；一个都不剩时，概要节点连同子节点变成父节点下的普通子节点，不删除。
  - 鱼骨图结构下不显示概要，切回其他结构时恢复。
- 查找替换：见“查找与替换”。
- 工具栏（见“工具栏与通用操作”）：插入区为子主题、同级主题、父主题、概要；格式区为背景色、边框色、文字颜色、字号、加粗、格式刷、恢复默认样式；其后是“折叠”下拉。“画布”下拉：结构、节点外观、线条、配色方案、主题间距。
- 右键节点：添加子主题 / 同级主题 / 父主题、概要、复制、剪切、粘贴、克隆、删除、折叠 / 展开、展开到第几层。

#### 流程图编辑

- 只在图上编辑，界面上不显示 Mermaid 文本，不提供文本编辑。
- 自由画布：节点可以拖到任意位置，位置写进文件。拖动时对齐到 10 像素的网格；靠近其他节点的中线或边时显示对齐线并吸附；按住 `Alt` 拖动不吸附。选中多个节点时一起拖动。
- 新建的流程图是空白画布。没有位置信息的流程图（外部写的，或更早版本的 Spark 写的）打开时按文件里的方向自动排一次；只打开不编辑不会写回文件，编辑后连同全部位置一起保存。

- 连线接在哪一边：从哪一边拖出、松开在目标的哪一边，就固定接在那里，写进文件；拖动节点时不再自动换边。改接端点时重新按松开的位置决定；也可以右键连线，在“起点接在 / 终点接在”里直接选上、下、左、右或自动。固定接边的直角走线不往回折、不穿过两端的节点，必要时绕到节点外侧。在外部写的、没有记录接在哪一边的连线，仍按两个节点的相对位置自动选边。
- 调整走线：直角和圆角连线可以按住其中一段拖动，沿垂直方向平移（如把底下的横段往下拉），选中连线时每段中间显示小手柄；拖首尾段时在节点边上留出一小段再平移。靠近两端的位置时吸附拉直，否则对齐网格，按住 `Alt` 不吸附。拖过的位置写进文件；只移动一端的节点时，拖过的段留在原处，首尾段随节点变化；两端节点一起移动或复制粘贴时整体平移。改接端点、改接边或 AI 整理后改回自动；右键连线“重置走线”也可改回自动。直线走线不能拖。
- 连线样式，每条连线单独设置：走线为直角（默认）、圆角、直线；线型为实线箭头、无箭头、虚线、粗线。直角和圆角走线自动折线，不避让其他节点，可以按段拖动调整（见上条）。
- 调整大小：选中单个节点时四角出现手柄，拖动手柄改变宽高（按住 `Shift` 保持比例），大小写进文件；文字在框内自动换行，框比文字小时框随文字变高。“恢复默认样式”同时恢复自动大小。
- 对齐与分布：选中两个及以上节点时，工具栏出现“对齐”下拉：左对齐、水平居中、右对齐、顶对齐、垂直居中、底对齐，水平等间距、垂直等间距（三个及以上节点时）；右键菜单里也有。
- 双击节点、文字或连线编辑文字；`Delete` 删除选中的节点（连同相连的连线）或连线；撤销和重做同思维导图。
- 方向键把选中的节点移动 10 像素，`Shift+方向键` 移动 50 像素。
- 右键节点：改为某种图形、编辑文字、复制、剪切、粘贴、克隆、对齐（多选时）、删除。右键连线：走线、线型、编辑文字、删除。
- 多选（`Shift+点击`、`Ctrl+点击`、框选）、点空白处取消选中、移动画布，都同思维导图。
- 工具栏（见“工具栏与通用操作”）：插入区为图形、文字；格式区选中节点时为形状、背景色、边框色、文字颜色、字号、加粗、格式刷、恢复默认样式，多选时另有“对齐”，选中连线时换成走线、线型；其后是“AI 整理”。“画布”下拉：配色方案、主题间距（AI 整理和首次打开自动排版时用）、新连线的走线和线型。

#### 工具栏与通用操作

- 两种图的工具栏布局相同，从左到右：插入区；撤销、重做、删除；格式区；图特有的按钮（思维导图的“折叠”、流程图的“AI 整理”）；右侧为“画布”下拉、查找、导出。不再有右侧样式面板。
- 格式区跟随选中的内容：没有选中时按钮显示为不可用，不改变位置；颜色按钮点开是 12 色色板、“无”和“更多颜色”；字号是四档下拉；加粗是开关。
- 格式刷：选中一个节点后点“格式刷”，再点别的节点（或框选多个）即把样式刷过去，刷一次后退出；双击“格式刷”可连续刷，按 `Esc` 或再点一次退出。流程图同时刷形状和大小。
- 缩放：画布右下角有缩放控件（缩小、比例下拉、放大、适应窗口）。`Ctrl+滚轮` 和触控板双指捏合以鼠标所在位置为中心缩放；`Ctrl+0` 适应窗口，`Ctrl+1` 恢复 100%；比例下拉里有常用比例。缩放比例仍存本机（5.18 文件）。
- 复制、剪切、粘贴、克隆（`Ctrl+C` / `Ctrl+X` / `Ctrl+V` / `Ctrl+D`）：
  - 思维导图：连同子节点和样式一起复制；粘贴为选中节点的子节点；克隆放在原节点后面作为同级节点；
  - 流程图：复制选中的节点以及它们之间的连线；粘贴到鼠标位置（鼠标不在画布上时放在视图中央），克隆放在原位置右下方错开一点；
  - 复制时同时往系统剪贴板写一份纯文字（思维导图按缩进，每层两个空格；流程图每个节点一行），可以粘贴到笔记或其他软件；
  - 从其他软件复制的多行文字：思维导图按缩进生成子树（列表符号 `-`、`*`、`1.` 自动去掉）；流程图每行一个节点，从上往下排开，不连线。
- `Ctrl+A` 全选（思维导图不含折叠起来的节点）。
- 右键空白处：新建（思维导图为子主题，流程图为图形和文字）、粘贴、全选、适应窗口。
- 节点文字可以换行：编辑时 `Shift+Enter` 换行。文件里换行写成 `<br>`（节点文字加引号），读回时还原成换行；文字里原有的 `<` 写成 `#lt;`。

#### 查找与替换

- 思维导图和流程图都支持 `Ctrl+F` / `Ctrl+H`（与笔记共用快捷键），使用与笔记相同的查找栏，支持区分大小写和正则。
- 范围：节点文字；流程图另含连线文字。命中的节点高亮，回车跳到下一个并选中，折叠的分支自动展开。
- 替换当前或全部替换；全部替换算一步操作，可一次撤销。

#### 无法显示

- 文件含不支持的语法或无法识别的内容时，不画图，也不显示文件内容，改为提示页：逐条列出原因（如“第 2 行用到了暂不支持的 subgraph（子图）”“第 5 行无法识别”），并提供“用系统默认程序打开”“在文件夹中显示”。
- 这类文件在 Spark 中不能编辑，也不会被改写；照常参与同步、Git、历史版本、改名、移动和删除；全文搜索只匹配文件名。
- 文件在外部被修改后，按新内容重新判断是否能显示。

#### 与笔记库的整合

- 文件树（4.5）、多标签页（5.7）、自动保存（5.2）、外部修改检测（7.3）、历史版本（5.8）、回收站（5.9）、快速打开（5.10）、WebDAV 同步（5.12）、Git（5.14）与笔记一致，差异写在各节中。
- 链接与反向链接见 5.3；图的标签页底部也有反向链接面板，列出链接了这张图的笔记。
- 全文搜索见 5.4。
- 大纲视图和标签视图不包含图。
- 图只作为链接的目标，节点不能链接到笔记（见第 8 章）。

#### 导出

- 图的工具栏“导出”菜单：导出 PNG、导出 SVG、复制为图片（PNG 写入剪贴板）。按当前显示的配色与样式，导出整张图，折叠的分支保持折叠。
- 导出 PDF 与“导出当前笔记”（第 8 章）一起实现。

#### AI 生成思维导图

- 两种生成方式，都遵循 5.16 的原则、配置、失败处理和长度上限：
  - **整篇笔记**：文件树中笔记的右键菜单“用 AI 生成思维导图”、命令面板“AI：把当前笔记生成思维导图”。
  - **按描述**：左栏“新建”下拉和文件树右键菜单的“AI 生成思维导图…”、笔记里选中文字后的右键菜单“用选中文字生成思维导图”、命令面板“AI：生成思维导图”、新建的空白思维导图（只有中心主题）下方提示里的“用 AI 生成”按钮。打开与“AI 生成流程图”同样布局的输入框：多行描述框（带示例提示）和布局选项（自动 / 向右 / 向左 / 左右平衡，默认自动；自动在一级分支达到 5 个时用左右平衡，否则向右），底部“生成 / 取消”，`Ctrl+Enter` 生成。从选中文字进入时预先填好选中的文字。描述超过长度上限时提示“描述过长”，“生成”不可用。
- 结果放在哪：整篇笔记生成的放在笔记所在文件夹，文件名 `笔记名 导图.mind.mmd`；按描述生成的放在当时选中的文件夹（从笔记进入的放在笔记所在文件夹），文件名取 AI 给的中心主题（去掉不能用作文件名的字符，最多 40 字），重名时加序号，绝不覆盖。从空白思维导图的提示进入时，直接画进这张图。
- 新开一个草稿标签页（按描述生成时标签页标题随 AI 给的主题更新），节点边生成边画出；生成期间图是只读的，顶部显示进度和“停止”（`Esc`），此时还没有写入磁盘。
- 结束后（完成、停止或出错）顶部改为“保留 / 丢弃”：保留则写入文件（画进空白思维导图的，写进这张图，算一步操作，`Ctrl+Z` 可以回到空白）；丢弃则关闭草稿标签页、不留下任何文件（画进空白图的恢复原样）。“重新生成”：整篇笔记生成的在停止或出错后出现；按描述生成的一直可用，重新打开输入框，可以改描述和布局。
- 程序按支持的语法解析 AI 的回复；无法识别的行不采用，并在“保留 / 丢弃”旁注明跳过了几行。

#### AI 生成流程图

- 入口：
  - 左栏“新建”下拉和文件夹的右键菜单“AI 生成流程图…”；
  - 命令面板“AI：生成流程图”；
  - 笔记里选中文字后的右键菜单“用选中文字生成流程图”；
  - 空白流程图中间的提示里的“用 AI 生成”按钮。
  遵循 5.16 的原则、配置、失败处理和长度上限。
- 输入框：一个多行描述框（带一句示例提示）和方向选项（自动 / 上到下 / 左到右，默认自动），底部“生成 / 取消”。从选中文字进入时，选中的文字预先填好，可以再改。描述超过长度上限时提示“描述过长”。
- AI 只给出流程的内容：一个简短标题、方向（选了“自动”时由 AI 决定）、节点、形状、连线和分支文字；节点位置由程序按分层排版算出（和 AI 整理一样），连线用直角走线；会穿过其他节点的连线（如回到前面的循环、跨层的分支）自动改从外侧绕开，并尽量不和别的连线挤在节点的同一边，接边和折点写进文件。约定：
  - 开始和结束用胶囊，判断用菱形，输入输出用平行四边形，数据或存储用圆柱，其余用矩形；
  - 节点文字尽量短（约 12 字以内），判断的每个分支都写连线文字（如“是 / 否”）；
  - 最多约 30 个节点，步骤太多时合并成较粗的步骤；不加文字说明节点。程序最多采用 60 个节点，超出时截断并注明。
- 上色由程序按形状决定，不交给 AI：胶囊用绿色系，菱形用琥珀色系，其余用主题默认色；深色主题下用对应的深色。颜色写进文件，保留后可以照常修改。
- 结果放在哪：
  - 默认新开一个草稿标签页，保留时写入 `标题.flow.mmd`（取不到标题时叫“流程图”，重名时加序号，绝不覆盖）。从文件夹或“新建”下拉进入的，放在当时选中的文件夹；从笔记进入的，放在笔记所在的文件夹；
  - 从空白流程图的提示进入时，直接画进这张图，同样要选“保留 / 丢弃”：保留则写进这个文件，算一步操作，按 `Ctrl+Z` 可以回到空白；丢弃则恢复空白，文件不变。
- 生成：节点边生成边画出，每收到一条完整的行重新排一次版；期间图是只读的，顶部显示进度和“停止”（`Esc`），此时还没有写入磁盘。
- 结束后（完成、停止或出错）顶部显示“保留 / 丢弃”、修改意见输入框、“重新生成”：
  - 修改意见：输入意见（如“审批改成两级”“驳回后回到提交”）后发送。发给 AI 的是原始描述、当前这一版流程图和这条意见，结果替换当前这一版并重新排版；
  - 回到上一版：修改后可以回到修改前的那一版（也可按 `Ctrl+Z`），只保留一级；
  - 重新生成：可以先改描述，再从头生成；
  - 草稿期间不能手动编辑，保留之后照常编辑和 AI 整理。
- 程序按支持的语法解析 AI 的回复；无法识别的行不采用，并在“保留 / 丢弃”旁注明跳过了几行；一个节点都没有时不能保留。出错时同时显示原因。关掉草稿标签页等于丢弃，同时停止请求。

### 5.19 表格簿

> 2026-10-08 新增。把同一主题的笔记、思维导图、流程图放在一起，像 Excel 工作簿那样在左下角用“表”切换。低保真原型见 `prototype/lowfi-workbook.html`。

#### 定位与存储

- 表格簿是和现有文件并存的第四种内容：不替换笔记、思维导图、流程图，不迁移任何已有数据。
- 一个表格簿 = 一个以 `.book` 结尾的文件夹（如 `周报.book/`，扩展名不区分大小写）；里面每张表都是普通的 `.md`、`.mind.mmd`、`.flow.mmd` 文件，三种类型可以混放，也可以放多张同类型的表（多页笔记）。类型只看扩展名，规则同 5.18。
- 文件夹里的 `.book.json` 只记录表的顺序：`{"version":1,"order":["本周.md","目标拆解.mind.mmd"]}`。表名就是文件名，不在清单里另存。
  - 文件夹里有、清单里没有的表追加到最后（按名称）；清单里有、文件已不存在的条目忽略。这样外部编辑、同步造成的不一致不会丢表。
  - 清单缺失时按名称排序；清单损坏（不是合法 JSON）时同样按名称排序，并在底部标签栏提示“顺序文件无法识别”，不改写文件，下次拖动排序时重新写入。
  - “上次停在哪张表”只存在本机设置里，不写进清单，避免多台设备互相改清单造成同步冲突。
- 同一个表格簿内表名不能重复，不分类型（不能同时有 `本周.md` 和 `本周.mind.mmd`），这样 `[[本周]]` 不会指向不明确。通过外部手段造成的同名不做处理，两张表都显示。
- 子文件夹、不认识的文件、嵌套的表格簿不作为表显示；以 `.` 开头的文件和 `*.assets/` 附件文件夹不算。有这类项目时底部标签栏末尾显示红色提示“有 N 个项目无法显示”，悬停列出名称，点击在资源管理器中打开这个文件夹。这些项目照常随文件夹同步、移动和删除。
- 表的附件仍是旁边的 `表名.assets/`，规则同 3.4。
- 保留后缀：普通文件夹不能新建或改名成以 `.book` 结尾；表格簿改名时自动保留 `.book` 后缀。

#### 文件树与标签页

- 文件树里表格簿显示为一个不能展开的文件节点，用专门的图标，名称不显示 `.book`；和文件排在一起，不和文件夹排在一起（文件夹始终在前）。其他项不能拖进表格簿，新建位置也不会落在表格簿里面（选中表格簿或正在看它里面的表时，新建到它所在的文件夹）。
- 点击表格簿打开它，停在本机上次看的那张表（没有记录或那张表已不存在时停在第一张）。表格簿总是以固定标签页打开；里面没有表时（被外部删光）自动补一张空笔记。
- 一个表格簿在顶部只占一个标签页，标题是簿名；里面各张表仍是各自独立的标签页（各自保存、各自的撤销历史），只是在顶部合并成一项显示。关闭这一项（`Ctrl+W`、标签上的 ×、中键）会关闭里面所有打开的表；“关闭其他 / 关闭右侧”和 `Ctrl+Tab` 切换都按这一项计算。
- 重启后恢复上次打开的表；收藏和“最近打开”记到表格簿这一级。

#### 底部标签栏

- 打开表格簿时，编辑区最下面（全局状态栏上方）多出一行表标签；不在表格簿里时不显示。左边是“+”，右边依次是各张表（类型图标 + 表名）；当前表白底加粗，底部有强调色线；AI 生成中的草稿表排在最后，虚线边框并带“草稿”标记。
- “+”：弹出笔记 / 思维导图 / 流程图，新表加在最后，自动叫“表 N”（取第一个没用过的数字），切换过去并进入改名状态；新思维导图的中心主题就是表名，新流程图是空白画布。
- 点击切换；`Ctrl+PageDown` / `Ctrl+PageUp` 切换到下一张 / 上一张表，到头后绕回（命令“表格簿：下一张表 / 上一张表”，可自定义）。当前表始终滚动到可见范围内。
- 双击标签或右键“重命名”，标签就地变成输入框：回车保存，`Esc` 放弃；名称为空、含文件名不允许的字符、以 `.` 开头或结尾、或和簿内别的表重名（不分类型）时，输入框变红并在上方提示原因，回车不生效；点别处离开时放弃改名并提示原因。改名就是改文件名，指向它的双链自动改写（同 5.3）。
- 拖动标签排序，蓝色竖线标出放下的位置，只改 `.book.json`。
- 右键菜单：重命名、复制、删除；笔记表上另有“用 AI 生成思维导图”“用 AI 生成流程图”。
  - 复制：在原表后面插入副本，叫“原名 副本”（重名时加序号），笔记的附件一并复制，切换到副本。
  - 删除：和删除文件一样先确认，确认后移入回收站（5.9），切到相邻的表。表格簿至少保留一张表，只剩一张时“删除”置灰（悬停提示“表格簿至少保留一张表；要删除整个表格簿，请在侧边栏操作”）。
- 表太多放不下时出现“‹ ›”滚动按钮和“☰”（列出全部表，点击跳转），也可以在标签栏上用滚轮横向滚动。
- 状态栏显示当前这张表的统计（笔记表是字数和行列，图是节点数和缩放比例）和它的保存状态。
- 切换表的行为与现有切换标签页一致：思维导图和流程图的缩放、折叠状态按表保存在本机设置里；笔记的光标位置和滚动位置不单独保留。

#### 文件树里的操作

- 新建：“新建”下拉菜单、右键菜单、文件菜单、命令面板“新建表格簿”（默认无快捷键）。新建后在文件树里就地输入名称，默认“未命名表格簿”（重名时加序号），同时打开它，里面已有一张空笔记“表 1”。标题栏标签页上的“+”和 `Ctrl+N` 仍然只新建笔记。
- 右键菜单与普通文件相同：新建…、重命名、隐藏、删除、收藏、复制路径、在资源管理器中打开；没有“用 AI 生成思维导图”（移到了表标签的右键菜单）。删除表格簿时确认框写“表格簿‘x’及其中的所有表”，整个文件夹移入回收站。
- 改名、移动表格簿时，指向它里面各张表的链接（`[[周报.book/本周]]`）和指向表格簿本身的链接（`[[周报.book]]`）都会自动改写，已打开的标签页跟着换路径，“上次停在哪张表”也跟着走。
- 从回收站恢复单独删除的一张表：放回原来的表格簿，清单里没有它，因此排在最后；表格簿也已被删除时，会重新建出这个文件夹，只包含这一张表。

#### 双向链接、搜索与 AI

- `[[周报.book/本周]]` 和 `[[本周]]`（规则同 5.3）打开表格簿并切换到那张表；`[[周报.book]]` 打开表格簿，停在上次看的那张表；显示时去掉 `.book` 后缀。指向不存在的表格簿时只提示，不提供创建。
- `[[` 补全里，表显示成“簿名 › 表名”（所在文件夹按表格簿算），表格簿本身也在列表里，选中时写入 `[[周报.book]]`；重名的表写成带路径的形式。按簿名也能搜到里面的表。
- 全文搜索、标签视图、反向链接、快速打开里，表都显示成“簿名 › 表名”；点击打开表格簿并切到那张表。表格簿本身不是反向链接的目标，只有它里面的表有反向链接面板。
- AI：在笔记表上“用 AI 生成思维导图 / 流程图”（标签右键菜单），以及在表里选中文字后“用选中文字生成…”，结果作为带“草稿”标记的临时表放进同一个表格簿，保留 / 丢弃 / 重新生成的规则同 5.18；保留后成为正式的表（重名时加序号），丢弃则标签消失。关闭表格簿时没保留的草稿直接丢弃。

#### 同步、历史与手机

- 每张表都是普通文件：历史版本、回收站、全文搜索、WebDAV 同步、Git 都按单个文件处理，每张表天然独立，同步冲突也只影响冲突的那张表。`.book.json` 跟着表格簿同步（WebDAV、Git、导出 zip 都带上它），两台电脑同时调整顺序时按文件的冲突规则处理；对不上的条目按上面的容错规则消化。
- 手机（只读）：文件列表里表格簿显示为一个条目（旁注“N 张表”），打开后停在第一张表，顶部标题是簿名，底部是只读的表切换条（横向滑动、点击切换，替换当前页，返回键仍回到列表）；不能新建、改名或排序。收藏、最近打开记到表格簿这一级；链接和搜索结果指向表格簿或其中的表时直接打开对应的表。

#### 当前不做

- 把已有的独立文件移进表格簿、把某张表移出成为独立文件（需要时在资源管理器里移动文件）。
- 导出整个表格簿（各张图表仍可用各自工具栏的导出）。
- 表格簿嵌套；跨类型的同名表。
- 笔记的光标和滚动位置按表单独保留（现有标签页也不保留）。

## 5.20 手机端书架、阅读与助手

安卓端底部是「文件 / 书架 / 助手 / 我的」。普通笔记、导图和流程图仍只从云端下载、不能编辑，只能删除（见下面「删除笔记」）。书架、读书笔记、书签、阅读进度和 AI 对话可以写回用户自己的 WebDAV。

- **文件**：搜索和最近打开都从文件页进入。文件页根目录顶部的搜索框通栏显示（和原型图 1-a 一致）。搜索是文件页的一个状态：顶部只剩输入框和「取消」，底部标签栏仍在，停在「文件」。笔记阅读页有右侧滚动条，并记住上次位置（只存在这台手机）。
- **返回**：用 Tauri 的安卓返回键事件接管返回键和各家手机的左右滑动返回（不靠 WebView 历史，阅读页 iframe 里翻页留下的历史不会吞掉返回）。先收起页面上的菜单、面板和确认框，再一级一级退回上一层，最后退到文件页根目录。已经在文件页根目录时，再返回一次先震动一下并提示「再按一次返回键退出」（页面同时左右弹一下），2 秒内再返回一次才回到手机桌面。
- **书架**：只显示手机里的书。可以从系统文件选择器导入 EPUB、TXT、MOBI、AZW3、PDF，再上传到云端目录 `spark-books`（和笔记库的 `spark/` 平级，用读书笔记库的 WebDAV 账号）。导入时系统文件选择器给的是 `content://` 地址，先拷到应用缓存目录再导入。云端的书在「云端」页按本下载，下载时这一行显示进度条和百分比；下载记在书架里，离开云端页照常进行，书架上同时显示“下载中 N%”，下完或失败时弹提示。书架每本书下面显示“未读 / 读到 N% / 已读完”，封面底部有进度条，TXT 另标“TXT”。封面：EPUB、MOBI、AZW3、PDF 第一次上架后在后台从书里取封面图，缩到 300px 宽存在手机里；取不到封面的书和 TXT 按书名用一种固定的颜色，上面写书名。删除云端的书先进入 `spark-books/.spark-trash/`。读书笔记库默认就是当前笔记库，已经连上笔记库不用再去设置里选；在「我的 → 书架」里选过别的库才用那一个。
- **添加笔记库**：填 WebDAV 地址、用户名、密码后点「连接」，列出云端 `spark/` 下已有的笔记库，选一个即可保存并开始同步（名称用文件夹名，远端目录是 `spark/<名称>`）。云端还没有 `spark/` 里的库，或笔记库不在 `spark/` 下（坚果云、Nextcloud 等）时，用「手动填写目录」。编辑已有笔记库仍是完整表单。
- **阅读**：EPUB、MOBI、AZW3 用 foliate-js，PDF 用同一套阅读器里的 PDF.js（用 pdf.js 的 legacy 版本，旧版安卓 WebView 缺少新的 JS 方法也能打开；它的 worker、字体和 CMap 由手机端构建原样拷到安装包里），TXT 按章节切开。TXT 先按 UTF-8 读，不是 UTF-8 就按 GBK 读；没有章节标题或章节很长时，每约 2 万字切成一页，避免一次排版整本书。下载和上传不设整个请求的总时限，只限制连接和每次读写的等待，网速慢也不会被半路掐断。左右翻页或上下滚动，记住阅读进度，并同步到 `spark-books/.spark/progress.json`。点屏幕中间约 40% 呼出或收起菜单，点左右两侧约 30% 翻页，也可以左右滑动翻页。左右翻页时可在阅读设置里选翻页动画「平移 / 淡入淡出 / 无动画」（默认平移），点两侧和左右滑动在各种动画下都能翻页。动画由阅读页自己做，阅读器只负责瞬间换页：平移时同一章里相邻的页本来就排在同一个 iframe 里，拖动和动画只移动这个 iframe（transform），滑到位后在同一帧里换页并去掉位移；跨章时下一章还没排版，改成淡入淡出；拖得不够远就弹回原处；已经是第一页或最后一页时提示。打开书时先用手机上记下的位置，不等网络，云端进度更新时再跳过去；书页排好、字体加载完才显示（最多等 1.5 秒），避免字体跳一下。菜单左上角的返回直接回书架。字号、行距、字体以样式表写进书页并压过书自带的样式。字体可选「书籍自带 / 宋体 / 楷体」：很多安卓手机只自带中文黑体，所以宋体（思源宋体 Noto Serif SC）和楷体（霞鹜文楷 LXGW WenKai）打包在安装包里，只含 GB2312 常用字，各约 1.6MB，字表外的字落到系统字体；两套字体都是 SIL OFL 1.1 许可，许可文本放在 `src/mobile/fonts/`。页边距是阅读器的左右留白。阅读主题作用于整个阅读页，包括四周留白、菜单、面板和状态栏（状态栏图标随深浅主题换色）。上下滚动时页脚单独占一行，不压正文。
- **读书笔记**：每本书自动建一篇笔记 `读书笔记/<书名>/<书名>.md`，只记自己写的感悟和读完后的总结。正文不写书名标题、章节名，也不摘录书里的原文。感悟按写下的先后排在一起，总结写在文末的「总结」一节。
- **划线、想法、书签**：长按选字时不显示系统的复制、分享工具条（阅读页打开时，安卓端把 WebView 的选字工具条菜单清空，选区和把手照常保留），只显示 App 的菜单（划线、写想法、复制、问 AI；点已有划线时是写想法 / 编辑想法、复制、问 AI、删除划线），菜单在选区上方，太靠上时放到下方；点别处或按返回关闭。菜单底部的「目录」打开「目录 / 笔记 / 书签」三个标签的面板（当前章节加粗带圆点，每章右侧是在全书的位置；笔记页只列出写过的感悟和总结，不显示章节名和书中原文；书签左滑露出“删除”，这一行跟着手指走）。底部「笔记」写一条感悟，不用先选字，也不把这一页的原文放进输入框或笔记里，不在书里画线。笔记页里的「总结」用来写读完后的总结。手机的笔记阅读页不显示记位置的 `<!-- spark-anno … -->` 注释。顶部书签按钮加上或去掉当前页书签，有书签时图标实心、页面右上角露出书签角。感悟、总结和划线的位置写在读书笔记库的 `读书笔记/<书名>/<书名>.md`，位置记在 HTML 注释里，原文摘录不写入这篇笔记。桌面编辑器不显示这段注释，保存时原样保留。书签写在 `spark-books/.spark/bookmarks.json`。
- **删除笔记**：文件页长按笔记、导图、流程图、表格簿或文件夹，底部菜单里可以删除。删除前确认，勾选「同时删除云端文件」时云端的移进云端回收站（`.spark-trash/`），电脑下次同步时也会删除；不勾选时只删这台手机上的，并记进这个笔记库的隐藏列表（`mobile/vaults/<id>.hidden.json`），以后同步当作云端没有它、不再下载。这是手机端唯一会改动普通笔记的操作。
- **旧版 WebView 兼容**：构建只转语法、不补 API（Vite 默认目标 Chrome 111）。foliate-js 解析 EPUB 用到的 `Object.groupBy`、`Array#at`、`findLastIndex` 以及 Pinia 用到的 `Object.hasOwn`，在 `src/mobile/polyfills.ts` 里补上（WebView 自带时不覆盖）。补上后按代码检查，系统 WebView 是 Chrome 94 以上时各格式都能打开（PDF.js 用到 class 静态块，界面用到 `inset`、`aspect-ratio`），没有在旧手机上实测。`color-mix()` 要 Chrome 111，更旧的 WebView 上淡色底和细边框换成主题里现成的颜色（`mobile.css` 末尾的 `@supports not` 一段）。foliate-js 书页样式里的 CSS 嵌套要 Chrome 112，更旧时竖排书的分栏设置不生效，横排书在手机上照样是单栏。
- **提示与确认**：确认框用应用自己的对话框（中文按钮，返回键或点遮罩取消），不用系统的 confirm。提示里常见的英文系统报错（找不到文件、网络超时等）换成中文，长的提示停留更久。
- **助手**：模型列表和 API Key 只存在这台手机（Key 在安卓系统密钥库）。会话不随笔记库同步。阅读页可以打开同一个助手。
- **笔记柜**：浏览器左侧有「书架」，列出书名、格式、大小和上传时间，可以上传、下载、把书移入回收站。上传可以一次选多本，逐本显示进度；有同名文件时问「覆盖」（旧文件先进书架回收站）还是「另存为 名字 (2)」，也可以跳过。`spark-books/` 不会出现在「未归库」。

## 7. 非功能需求

### 7.1 性能指标

基准：Windows 10/11，**1 万篇笔记（以图片附件为主）**的笔记库。

| 指标 | 目标 | 实测（2026-09-28） |
| --- | --- | --- |
| 冷启动到可编辑 | < 1 秒（索引已存在时） | 445ms |
| 空闲内存（Spark 进程 + 页面进程） | < 100MB | 46MB |
| 打开万篇笔记库后内存（Spark 进程 + 页面进程） | < 200MB | 99MB |
| 全文搜索响应 | < 200ms | 8–199ms（启动后第一次查询最慢） |
| 打开单篇笔记（< 100KB） | < 100ms | 75–93ms |
| 打开单篇笔记（约 1MB） | < 0.5 秒 | 约 400ms |
| 输入延迟 | 无可感知卡顿（< 16ms） | 约 1MB 的笔记中连续输入，帧间隔 16.7ms，无掉帧 |
| 首次建立 1 万篇索引 | 后台进行，不阻塞编辑 | 3–9 秒（取决于文件是否已在系统缓存中），期间打开笔记不受影响 |
| 安装包体积 | < 20MB | MSI 4.7MB，NSIS 3.5MB |
| 打开 200 个节点的思维导图或流程图 | < 200ms | 未测（5.18） |
| 在 200 个节点的图上编辑一次，到重新排版完成 | < 50ms | 未测（5.18） |
| 5.18 带来的安装包增量 | < 1MB（MSI 总量 < 6MB） | 2026-09-29（不含结构、样式、概要）：MSI 4.9MB、NSIS 3.68MB，各增加约 0.2MB |

- 内存口径（2026-09-28 调整）：只统计 Spark 进程和 WebView2 的页面（renderer）进程。WebView2 运行时的公共进程（GPU、浏览器主进程、工具进程）不论界面内容都约占 150MB，属于系统组件开销，单独记录，不计入指标：实测不打开笔记库时合计 196MB、打开万篇笔记库后合计 262MB。
- 打开单篇笔记（2026-09-28 调整）：原指标“< 1MB 的笔记 < 100ms”拆为两档。读取约 1MB 的文件只需约 10ms，其余时间是编辑器解析与渲染全文。
- 测量方法：`scripts/perf/` 中的脚本生成 1 万篇笔记（一半带图片）的测试库，用发布版经 WebView2 远程调试接口测量，见 README“性能验收”。
- 5.18（2026-09-29 新增）：测试库中加入思维导图和流程图文件后，冷启动、内存、搜索、建立索引的指标不变；另加 200 个节点的图用于测量打开和编辑。

实现要求：

- 文件树虚拟滚动，大目录不卡顿。
- 索引、同步、文件监听在 Rust 侧后台线程执行。
- 编辑器的非必需模块按需加载。

### 7.2 可靠性

- 任何情况下不丢用户数据：原子写入、冲突两份都保留、删除进回收站、历史快照。
- 错误不吞：所有失败都向用户明确提示，并写入本地日志。
- 应用崩溃后重启，未保存内容可恢复。

### 7.3 兼容性

- 笔记文件为标准 Markdown，可被其他 Markdown 工具直接打开与编辑。
- 思维导图和流程图为 Mermaid 文本加 Spark 的扩展注释，只保证 Spark 能正确显示；在外部加入 Spark 不支持的语法后，Spark 不再编辑该文件（见 5.18）。
- 外部修改笔记或图的文件时自动检测并刷新；若当前笔记或图有未保存修改，提示用户选择。

### 7.4 安全

- WebDAV 密码、Git 远程密码与 AI 的 API Key 存在 Windows 凭据管理器或 macOS 钥匙串，不写入配置文件。
- 日志中不记录密码、API Key、笔记内容和发给 AI 的内容。
- 笔记内容只在用户主动点击 AI 功能时发送给用户配置的服务商（见 5.16）。

## 9. 默认假设（讨论中未逐项确认，请检查）

以下细节在讨论中未单独确认，文档中按常见做法设定了默认值，如有不同意见请指出：
