## 1. 产品概述

### 1.1 定位

Spark 是一款面向**个人单用户**的桌面端 Markdown 笔记软件。核心诉求：

- 记录体验接近 Typora：所见即所得的 Markdown 编辑，代码块语法高亮。
- 数据完全由用户掌控：笔记就是磁盘上的普通 `.md` 文件，拷走文件夹即可迁移。
- 可同步到用户自己的存储（WebDAV 或 Git 远程仓库），多台电脑间保持一致；也可用 Git 在本地做版本管理。
- **轻量、高性能**：低内存占用、快速启动、大库下搜索依旧迅速。
- **可选的 AI 辅助**：用户自己配置 AI 服务（OpenAI 兼容接口），只在用户主动点击时发送内容（见 5.16、5.17）。

### 1.2 目标用户

仅作者本人（单用户，无账号体系，无协作）。

### 1.3 运行平台

- Windows 10/11、macOS、Linux（技术上保证跨平台）。
- 第一版以 **Windows** 为主要验证平台。
- 不做移动端。

### 1.4 非目标（明确不做）

- 多用户、账号注册登录、多人协作/共享。
- 自建同步服务端。
- 富文本/私有格式存储、块编辑器数据模型。
- 移动端应用。

## 2. 技术选型

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 应用框架 | Tauri 2 | 使用系统 WebView，安装包约 10MB，内存远低于 Electron |
| 后端 | Rust | 文件 IO、索引、同步等重任务放在原生侧 |
| 前端 | Vue 3 + TypeScript | — |
| 编辑器 | Milkdown（基于 ProseMirror） | 成熟的 Markdown 所见即所得方案，体验接近 Typora |
| 代码高亮 | Prism（`@milkdown/plugin-prism` + refractor） | Milkdown 官方插件直接集成；Shiki 需额外的 wasm 引擎与语法包，体积大得多 |
| 全文搜索 | SQLite FTS5 + 中文二元切分 | 本地索引，毫秒级查询；不依赖词典，安装包不增大 |
| 凭据存储 | 系统凭据库（Windows 凭据管理器 / macOS 钥匙串 / Linux Secret Service）；Rust 侧直接调用 Windows 凭据管理器 API（M7 已实现，AI 复用） | 不明文保存 WebDAV 密码、Git 远程密码与 AI 的 API Key |
| AI 接口 | OpenAI 兼容的 Chat Completions 接口，Rust 侧沿用 M7 引入的 `ureq` 发请求（SSE 流式输出） | 一套协议覆盖国内外主流服务商与本地模型；Key 不进入前端页面，也没有跨域问题；不新增 HTTP 依赖 |
| 一键整理（规则版） | 中英文空格用 `pangu`（无依赖，持续维护）；全角转半角、中文标点、行尾空格等几条确定的字符规则自行实现并有单元测试 | `zhlint` 自 2024-08 未更新，且依赖 `glob`、`chalk` 等命令行包，不适合打包进前端 |
| AI 对话的 Markdown 显示 | `markdown-it`（关闭 HTML）+ 现有的 Prism 代码高亮 | 成熟、体积小，默认不渲染 HTML，AI 回复里的标签不会被执行 |

原则：优先复用成熟开源组件，不自研编辑器与搜索引擎。

## 3. 数据与存储

### 3.1 笔记库（Vault）

- 一个笔记库 = 磁盘上的一个普通文件夹。
- 支持**多个笔记库**，可新建、打开已有文件夹、切换、从列表移除（不删除磁盘文件）。
- 笔记库内的文件夹结构即左侧目录结构。

### 3.2 目录布局

```
我的笔记库/
├── 工作/
│   ├── 周报.md
│   └── 周报.assets/          # 附件（默认模式：与笔记同名的文件夹）
│       └── image-20260924.png
├── 个人/
│   └── 读书笔记.md
├── assets/                   # 附件（可选模式：统一目录）
└── .ttnote/                  # 应用数据目录（隐藏）
    ├── config/               # 同步 ✅：收藏、自定义排序、笔记库级设置
    ├── cache/                # 不同步 ❌：搜索索引等，可删除重建
    ├── history/              # 不同步 ❌：历史版本快照
    ├── trash/                # 不同步 ❌：回收站
    └── sync/                 # 不同步 ❌：同步状态记录
```

### 3.3 笔记文件格式

- 标准 Markdown（CommonMark + GFM 扩展：表格、任务列表、删除线等）。
- **文件名即标题**，正文不强制包含 `# 标题`。
- 元数据写在文件开头的 YAML Front Matter 中：

```markdown
---
tags: [工作, 周报]
created: 2026-09-24T15:00:00+08:00
---

正文内容……
```

- 标签同时支持 Front Matter 中的 `tags` 与正文内的 `#标签` 写法，两者合并展示。
- 用其他 Markdown 编辑器打开不丢失任何信息。

### 3.4 附件

- 支持粘贴、拖入图片及文件，自动复制到附件目录并插入相对路径引用。
- 附件存储位置可在设置中选择：
  - **默认**：笔记旁的同名文件夹 `笔记名.assets/`
  - 可选：笔记库根目录 `assets/`
- 笔记重命名/移动时，附件目录随之移动，引用路径自动更新。

### 3.5 本地迁移

- **整库拷贝**：将笔记库文件夹复制到另一台电脑，用 Spark“打开文件夹”即可使用，无需任何转换。
- **导出/导入**：
  - 导出笔记库为 `.zip`（包含笔记、附件与 `.ttnote/config/`，不含缓存/历史/回收站）。
  - 从 `.zip` 导入为新笔记库。

### 4.5 文件树交互

- 无限层级文件夹，展开/折叠状态记忆。
- 顶部按钮：新建笔记、新建文件夹、全部折叠、排序方式。
- 新建位置：选中的文件夹；选中的是笔记时用它所在的文件夹；没有选中项时用当前笔记所在文件夹；都没有则为根目录。新建后命名为“未命名”（重名时加序号），并在文件树中直接进入改名状态。
- 重命名：F2、右键菜单或正文大标题；删除：Delete 键或右键菜单。
- 排序：按名称 / 修改时间 / 创建时间，升序或降序；另支持**手动拖拽自定义排序**（顺序保存在 `.ttnote/config/`，随同步）。
- 拖拽移动文件/文件夹；移动后自动更新双向链接与附件引用路径。
- 右键菜单：新建笔记、新建文件夹、重命名、删除（进回收站）、收藏/取消收藏、复制路径、在资源管理器中打开。
- 当前打开的笔记在树中高亮并自动定位。
- 已收藏的笔记在树中行尾显示星标。
- 仅展示 `.md` 文件与文件夹；隐藏 `.ttnote/` 及 `*.assets/` 附件文件夹。

### 4.6 正文区

- 正文顶部用大字显示笔记标题（即文件名），可直接点击修改，回车或失去焦点即重命名文件，Esc 取消；标题下方显示标签与创建日期。
- Markdown 编辑区（见第 5 章）。
- 正文底部显示**反向链接**面板：列出所有引用当前笔记的笔记及上下文片段，可折叠。

### 4.7 状态栏

高度约 24px，显示：字数与字符数（有选区时显示选区统计）、光标行列、保存状态、同步状态与最近同步时间。编辑器只有所见即所得一种模式，不显示模式切换。

## 5. 功能需求

### 5.1 编辑器

- **所见即所得**（默认）：输入 Markdown 语法即时渲染（如输入 `# ` 变标题、`**文字**` 变粗体）。
- 只提供所见即所得一种编辑模式，不提供源码模式。
- 支持元素：标题、段落、粗体/斜体/删除线/高亮、行内代码、链接、图片、引用、有序/无序/任务列表、表格（可视化增删行列）、分割线、脚注。不支持数学公式与 Mermaid 图表（2026-09-28 从需求中删除）。
- **代码块**（Typora 风格）：
  - 输入 ```` ``` ```` + 语言名 + 回车，或从工具栏/斜杠菜单插入，生成独立代码框。
  - 代码框内按所选语言语法高亮，颜色随主题切换。
  - 代码框右上角可选择语言（带搜索）、一键复制代码。
  - 代码框内 `Tab` 缩进、回车保持缩进，不触发 Markdown 渲染。
  - 可选显示行号（设置项）。
- 查找与替换（`Ctrl+F` / `Ctrl+H`），支持大小写与正则。
- 格式快捷键见 4.3 工具清单，可自定义（见 5.13）。

### 5.2 自动保存

- 停止输入约 1 秒后自动写入磁盘；`Ctrl+S` 立即保存。
- 切换笔记、关闭标签页、退出应用前确保保存完成。
- 写入采用“写临时文件 → 原子替换”，避免断电导致文件损坏。

### 5.3 双向链接

- 输入 `[[` 弹出笔记名补全，生成 `[[笔记名]]` 链接；支持 `[[笔记名|显示文字]]` 与 `[[笔记名#标题]]`。
- 同名笔记：只写笔记名时优先解析到同一文件夹的笔记，其次路径最短的；补全时遇到重名笔记自动写成带路径的形式，如 `[[工作/周报]]`。
- `Ctrl+点击` 或直接点击（所见即所得模式下）跳转；目标不存在时提示是否创建。
- 笔记重命名/移动时，自动更新所有引用它的链接。
- 正文底部显示反向链接（见 4.6）。

### 5.4 全文搜索

- 搜索范围：标题（文件名）、正文、标签。
- 基于 SQLite FTS5 本地索引，中文按相邻两字切分（二元切分），**两个汉字的词也能命中**，任意连续文字都能搜到（偶尔会命中跨词的结果）。
- 搜索语法：空格分隔的词都要出现；`#标签` 按标签过滤（含子标签）；`path:文件夹` 按文件夹过滤。
- 结果显示笔记名、路径、命中片段（关键词高亮），点击打开并定位到命中处。
- 支持按标签、文件夹过滤。
- 索引增量更新；索引损坏或丢失时自动重建。
- 监听磁盘文件变化（外部编辑器修改、同步拉取），自动更新索引与界面。

### 5.5 标签

- 来源：Front Matter `tags` 与正文 `#标签`。
- 左栏标签视图展示全部标签及数量；支持层级标签 `#工作/周报`（按 `/` 分层展示）。

### 5.6 收藏

- 笔记与文件夹均可收藏，收藏列表在左栏“收藏”视图，可拖拽排序。
- 收藏数据存于 `.ttnote/config/`，随同步。

### 5.7 多标签页

- 同时打开多篇笔记，每个标签页独立保留滚动位置与撤销历史。
- 单击文件树为“预览标签页”（斜体标题，再次单击其他笔记会替换它），编辑或双击后固定。
- 重启应用后恢复上次打开的标签页。

### 5.8 历史版本

- 保存时对笔记做本地快照，存于 `.ttnote/history/`，**不同步**。
- 节流：同一篇笔记 5 分钟内最多保留一份快照。
- 默认保留 30 天，可在设置中调整。
- 查看某笔记的历史版本列表（文件菜单或命令「历史版本」），预览任一版本、按行与当前已保存内容对比、恢复到该版本（恢复前当前内容也会存为一份快照）。保留天数在设置中调整，0 表示不自动清理。

### 5.9 回收站

- 删除前弹出确认框；确认后笔记/文件夹（含附件）移入 `.ttnote/trash/<时间戳>/`，保留原相对路径并记录原位置，**不同步**。
- 可查看、恢复到原位置、彻底删除、清空回收站。
- 默认保留 30 天后自动清理，可在设置中调整。

### 5.10 命令面板与快速打开

- `Ctrl+P`：快速打开，按笔记名模糊搜索（字符按顺序出现即命中，连续命中排在前面）；未输入时列出最近打开的笔记；输入 `>` 切换到命令面板。
- `Ctrl+Shift+P`：命令面板，可执行所有命令，显示分类与当前快捷键；未输入时先列出最近使用的 5 条命令（应用级设置）。

### 5.11 主题

- 五套内置主题，分为两组：
  - 浅色系：**浅色**（冷灰 + 靛青）、**纸张**（米黄底 + 赭红强调）、**护眼**（浅豆沙绿底 + 墨绿强调）
  - 深色系：**夜读**（深蓝灰 + 琥珀强调）、**纯黑**（接近纯黑的底色，强调色沿用夜读的琥珀色）
- 各主题的布局、字体、尺寸完全相同，只替换配色；代码高亮、成功 / 危险等状态色同步切换，见设计稿。
- 正文元素配色：常用元素各有固定色系，五套主题里色系不变，只调深浅以保证对比度。笔记正文、AI 待确认区域、AI 对话回复使用同一套配色，不提供关闭开关。
  - 双向链接、列表圆点与序号：主题强调色
  - 外部链接：青色
  - 行内代码：玫红文字 + 同色淡底，无边框
  - 引用块：蓝色左竖线 + 同色淡底，右侧圆角
  - 任务列表：未勾选为淡绿边框；已勾选为绿色实心框，已完成项文字变灰并加删除线
  - 标签（Front Matter 标签与行内 `#标签`）：紫色文字 + 同色淡底
- 不提供“跟随系统”，不支持自定义主题。
- 切换方式：
  - 标题栏右侧的月亮/太阳按钮：分别记住上次使用的浅色系主题和深色系主题，点击在两者之间切换。当前为深色系时显示太阳，浅色系时显示月亮；按钮提示写明要切换到的主题，如“切换到纯黑”。首次使用时分别为浅色和夜读。
  - 视图菜单“主题”：列出五套主题，两组之间用分隔线隔开，当前主题打勾。
  - 设置 → 外观：单选列表，每项前有色块，显示该主题的标题栏底色、正文底色和强调色。
  - 命令面板：“切换深浅主题”（即标题栏按钮的操作），以及“主题：浅色”“主题：纸张”等直接选择某套主题的命令；均默认无快捷键，可自定义。
  - 从任何入口选中一套主题，都会更新它所在分组“上次使用”的记录。
- 选择结果存为应用级设置（每台电脑各自一份，不随笔记库同步）；启动时在窗口显示前应用主题，不出现闪白。

### 5.12 同步（WebDAV）

> 每个笔记库在“不同步 / WebDAV / Git（见 5.14）”中选一种同步方式，不能同时开启。

#### 配置

- 按笔记库分别配置：WebDAV 地址、用户名、密码、远端目录。
- 密码存入系统凭据库，不写入任何配置文件。
- “测试连接”在按钮旁直接显示结果，例如“连接成功，云端目录里有 36 篇笔记”；远端目录不存在时说明第一次上传会自动创建。
- 保存后读一次云端列表，第一次使用时给出建议：云端为空建议“上传”，本地为空建议“从云端同步”，两边都有时让用户选以哪边为准。
- 兼容坚果云、Nextcloud、群晖 NAS、Alist 等常见 WebDAV 服务；不支持 `Depth: infinity` 的服务逐层读取目录，任何一层读取失败都中止，不能当成空目录。

#### 同步范围

- 同步：笔记、附件、`.ttnote/config/`。
- 不同步：`.ttnote/cache/`、`history/`、`trash/`、`sync/`，以及云端回收文件夹 `.spark-trash/`。

#### 原则与触发方式

- **云端是正本**，本地是工作副本。两个手动操作，从标题栏同步图标的菜单进入（菜单里同时显示上次同步时间和各自的待处理数）：
  - **上传本地改动**：本地 → 云端。
  - **从云端同步**：云端 → 本地，以云端为准。
- 默认只在用户点击时执行。设置里有两个开关：
  - “打开笔记库时检查云端更新”（默认开）：只读取云端文件列表，不下载，有更新时图标提示；
  - “停止编辑 1 分钟后自动上传”（默认关）：只处理不需要确认的新增和修改，需要确认的留在菜单里等用户处理。
- 程序永远不会自动改动本地文件。
- 从旧版升级时，原来的双向自动同步一律改成手动（自动上传关闭），并用浮动提示说明一次。

#### 同步机制

- 本地记录上次同步时各文件的状态（哈希、修改时间、远端 ETag），与本地、远端当前状态比较，判断每个文件在两边各自有没有变。只传输有变化的文件。
- **上传**：本地新增或修改的文件传到云端。云端那份也被别的电脑改过时，覆盖前把云端旧版本移到云端回收文件夹；本地删掉的文件，云端移到云端回收文件夹。本地删了但云端被改过的，保留云端版本。
- **从云端同步**：云端新增或修改的文件下载到本地；本地改过的笔记被覆盖前存一份历史版本（附件移进回收站）；云端删掉的文件，本地移进回收站；本地新建、还没上传的文件保留不动并提示。
- **执行前的清单**：本次操作会覆盖或删除文件时，先弹出清单（按“覆盖、移除、新增、更新、保留”分组，可逐个取消勾选），确认后才执行；只新增和更新时直接执行。执行前重新读取两边，清单之外的覆盖和删除一律跳过。
- **云端回收文件夹**：`.spark-trash/<日期>/<时分秒>/<原路径>`，超过回收站保留天数（见 5.9）的日期目录在上传时删除；保留天数为 0 时不清理。
- **防丢数据**：上次同步时云端有文件、这次读到空的，或上次有 10 个以上文件、这次少了一半以上时，判定云端目录异常，停止执行并提示检查地址和目录；用户勾选“我确认云端就是这样，继续”后才执行。
- 执行过程中用户又保存了某个文件时，这个文件本次跳过，下次再按最新状态判断。
- 所有失败（网络中断、认证失败等）都明确提示原因，不静默失败。
- 同步不加密（第一版）。

### 5.14 Git 版本控制

#### 定位与实现

- 本地提交随时可用，用于留存历史、回退；配置远程仓库后可拉取和推送，作为同步方式之一（见 5.12，与 WebDAV 二选一）。
- 调用系统已安装的 `git` 命令，沿用用户现有的 Git 配置和 SSH 密钥。HTTPS 远程可以在软件里填写账号和密码（或访问令牌），只保存在系统凭据库里；没有填写时沿用系统凭据管理器里已有的账号，但不让它弹出自己的登录窗口。
- 与历史版本（5.8）相互独立：本地快照兜住两次提交之间的编辑，Git 记录有意义的里程碑。

#### 仓库

- 整个笔记库文件夹即一个仓库。`.ttnote/cache/`、`.ttnote/history/`、`.ttnote/trash/`、`.ttnote/sync/` 自动写入 `.gitignore`；`.ttnote/config/`（收藏、自定义排序）要提交。
- 笔记库已经是 Git 仓库时直接沿用，只在 `.gitignore` 中补上缺少的规则。不是仓库时，用户在同步设置里选了 Git 并点“连接”，或在版本控制视图点“初始化仓库”，才执行 `git init`。
- 只在当前分支上工作，不提供切换 / 新建分支界面。处于分离 HEAD、正在合并或变基时，禁用提交、拉取、推送并提示原因。

#### 提交

- 默认手动：填写提交说明后点击“提交”（`Ctrl+Enter`），提交全部改动（相当于 `git add -A`）。
- 可在设置中开启自动提交：停止编辑 5 分钟（可调）后提交一次；退出软件时如有未提交改动也提交一次。
- 自动提交的说明自动生成，形如 `自动提交：修改 3 篇（周报、读书笔记、WebDAV 同步设计）`，最多列出 3 个笔记名，超出用“等”；新增、删除同样写明。自动提交属于后台操作，不调用 AI。
- 手动提交时可以点提交说明下方的“AI 生成说明”，由 AI 根据改动写说明（见 5.16）。
- 提交身份不需要用户填写：已有全局 Git 配置时直接用；没有时自动生成并只写入本仓库（`git config --local`）。用户名取远程账号，没有账号时取系统用户名；邮箱用不会收信的地址（GitHub 为 `账号@users.noreply.github.com`，其他为 `账号@users.noreply.<域名>`）。可在 Git 设置的“高级”里修改。

#### 拉取与推送

- 只支持手动，不提供自动拉取 / 推送。操作均通过按钮完成，无需输入命令：
  - 标题栏同步图标：一键同步（先拉取再推送），悬停显示领先 / 落后远程的提交数；
  - 版本控制视图顶部：单独的“拉取”“推送”按钮。
- 拉取（含一键同步）前若有未提交的改动，或已提交但还没推送的提交里删掉了远程仍有的文件，先列出这些改动（按删除、修改、新建、未推送的删除分组），让用户选择：
  - **以仓库为准**：放弃本地改动，包括还没推送的提交，和远程仓库保持一致。删掉的恢复回来，改过的笔记恢复成远程版本（当前内容先存为历史版本），远程没有的文件和改过的附件移进回收站；然后拉取。
  - **保留本地改动并合并**：先自动提交一次（说明为 `拉取前自动提交：……`），再拉取合并。本地删除的笔记推送后在仓库里也会被删除。
  - 取消。
  不再静默自动提交：本地误删的笔记被自动提交后，拉取无法把它恢复回来，推送后远程也会被删除。
- 首次拉取时远程是空仓库或还没有当前分支，跳过拉取；远程只有网页上建仓库时生成的提交（如 README）时，允许合并无共同历史的分支。
- 首次推送时远程没有对应分支，自动执行 `git push -u origin <当前分支>`。
- **连接远程仓库**（设置页“同步 → Git”和「Git 设置」弹窗用同一套流程）：
  1. 填写远程地址，点“连接”：需要时初始化仓库，设置 origin，实际访问一次远程（`git ls-remote`）；
  2. HTTPS 仓库要求登录时，就地显示“账号”和“访问令牌”，认得 GitHub、Gitee、GitLab 时给出“去创建访问令牌”的链接；填写后点“登录并连接”再次验证；
  3. 连接成功后说明远程的情况并给出第一步按钮：远程为空时“推送本地笔记”，远程有笔记、本地没有提交时“拉取远程笔记”，两边都有时“开始同步”（先拉取再推送）；
  4. 本地分支还没关联远程、远程也没有同名分支时，把本地分支改成远程默认分支的名字（如 `master` 改成 `main`），避免拉不到远程的笔记。
- **登录失效**：拉取 / 推送时远程要求登录或拒绝了已保存的账号，弹窗填写，保存后自动重试刚才的操作。
- **冲突**：笔记文件冲突时与 WebDAV 规则一致，两份都保留（远程版本为原文件，本地版本另存为 `笔记名 (冲突 电脑名 日期).md`），自动完成合并提交并提示用户手动合并；非笔记文件（图片等）冲突时中止合并，提示用外部 Git 工具处理。
- 远程仓库地址在设置中填写（相当于 `git remote add origin`），也显示已有的远程仓库。M5 放在独立弹窗「Git 设置」里（版本控制视图、命令面板，以及尚未配置远程时点击标题栏同步图标）；M6 并入设置页。自动提交的开关和等待时长存在 `.ttnote/config/git.json`。
- 所有 Git 失败（未安装、认证失败、网络错误等）都明确提示原因。所有操作结果用窗口右上角的浮动提示显示（成功的几秒后消失，失败的保留到手动关闭），设置窗口里的测试、保存、连接结果直接显示在按钮附近。未检测到 Git 时，版本控制视图提示安装并给出下载链接，其他功能不受影响。

#### 第一版不做

- 勾选部分文件提交、查看差异（与历史版本的对比界面一起在后续实现）、分支管理、Git LFS。

### 5.15 一键整理（规则版）

- 按固定规则整理当前笔记的文字格式，**不联网、不调用 AI**，结果可预测。
- 入口：格式工具栏“一键整理”按钮、命令面板，默认快捷键 `Ctrl+Shift+L`（可自定义）。
- 范围：有选中文字时只整理选中部分，否则整理整篇。代码块、行内代码、链接地址、Front Matter 一律不改。
- 整理结果算一步操作，`Ctrl+Z` 一次撤销。完成后在状态栏提示改了多少处（按规则分类计数）；没有需要整理的地方时提示“没有需要整理的地方”。
- 规则（设置 → 编辑器中每条单独开关）：

| 规则 | 默认 |
| --- | --- |
| 中文与英文、数字之间加空格 | 开 |
| 中文句子里的半角标点改为全角（`,` → `，`） | 开 |
| 全角英文和数字改为半角（`ＡＢＣ１２３` → `ABC123`） | 开 |
| 合并连续的空行 | 开 |
| 去掉行尾空格 | 开 |
| 修正标题跳级（H1 下面直接是 H3 时改为 H2） | 关（会改变结构） |

- 规则细节：
  - 中英文空格：行内代码整体按英文处理（与中文之间也加空格），代码内部不动；双向链接、图片前后不加空格。
  - 中文标点：只转换 `,` `;` `:` `?` `!` `.` 六种，且前一个字符必须是中文（或双向链接后紧跟中文）；`.` 还要求后面是结尾、空白或中文，因此 `1.0`、`readme.md`、`...` 不受影响；转换后去掉标点前后多余的空格。括号不转换。
  - 空行：同一层级里连续的空段落只保留一个。
- Markdown 语法层面的统一（列表符号、强调符号等）由编辑器保存时完成，不属于本功能。
- 实现：在编辑器的文档结构上逐个文本片段应用规则，加粗、链接等格式原样保留；排版规则见第 2 章。

### 5.16 AI 功能

#### 原则

- **只在用户主动点击时发送内容**，后台不自动发送任何笔记；需要后台运行的功能（如自动提交）不调用 AI。
- 每次发送前在界面上说明发送了什么（如“附带当前笔记，约 1,286 字”）。
- 所有 AI 请求都可以随时取消，取消后不写入任何内容。

#### 配置（设置 → AI）

- 只支持 **OpenAI 兼容接口**；接口地址和 API Key 只有一套，可以填写多个模型，第一个是默认模型，AI 指令、总结、整理结构、提交说明都用默认模型；AI 对话里可以临时切换（见 5.17）。
- 每个模型有一个**上下文长度**（tokens），按以下优先级确定：手动填写 > 服务商模型列表接口返回的值（点“从服务商读取”，部分服务商支持）> 内置的常见模型表（qwen、deepseek、kimi、glm 等）> 默认 128K。设置里显示每个模型的上下文长度及其来源。
- 字段：服务商预设（DeepSeek、通义千问、Kimi、智谱、硅基流动、OpenRouter、Ollama（本机）、LM Studio（本机）、自定义；预设只负责填好接口地址）、接口地址、API Key、模型列表（模型名、上下文长度，可添加、移除，“从服务商读取”）、“测试连接”按钮（用默认模型发一条很短的请求，显示成功或具体失败原因）。
- API Key 存入系统凭据库，不写入任何配置文件；界面上只显示“已保存”，可修改或清除。接口地址和模型名存为应用级设置。
- 不提供温度等高级参数，不允许修改提示词（后续有需要再加）。
- 未配置时点任何 AI 功能，先提示“尚未配置 AI”并提供“打开设置”。

#### 调用与失败处理

- 请求从 Rust 侧发出，流式返回，界面逐字显示。
- 网络错误、限流（HTTP 429）自动重试 1 次；认证失败、余额不足、超出上下文长度等直接显示具体原因，并提供“重试”。
- 60 秒内没有收到任何内容算超时。
- **长度上限按所用模型的上下文长度计算**：可发送的 token 数 = 上下文长度 − 给回复预留的部分（8K 与上下文长度的 10% 取较小者）。token 数在本地估算（中文约 1 字 1 token，其他文字约 4 个字符 1 token），界面上标“约”。超过上限时：AI 指令、总结、整理结构直接提示“笔记过长”；生成提交说明时每个文件只保留开头部分的差异。
- **每次请求的上下文相互独立**：AI 指令、总结、整理结构、提交说明每次只发送本次需要的内容，不带任何历史；AI 对话的每个会话只带本会话自己的消息，不同会话、不同功能之间互不共享。
- 日志中不记录 API Key 和发送的笔记内容。

#### 功能清单

| 功能 | 入口 | 发送内容 | 结果处理 |
| --- | --- | --- | --- |
| AI 指令 | 斜杠菜单“AI 指令” | 用户输入的指令；默认附带当前笔记全文，可取消勾选只发送指令 | 在光标处插入**待确认区域**，回答逐字流入，可停止；完成后“接受 / 放弃 / 重新生成”。接受算一步操作，可撤销；放弃不留痕迹 |
| 总结当前笔记 | 工具栏 AI 下拉、命令面板 | 当前笔记全文 | 弹窗显示，可“复制”或“插入到笔记开头”（插成引用块），可重新生成 |
| AI 整理结构 | 工具栏 AI 下拉、命令面板 | 当前笔记全文 | 见下文 |
| 生成提交说明 | 版本控制视图“AI 生成说明” | 本次改动的差异；改动过大时只发文件列表和每个文件的部分差异，并在界面说明 | 填进提交说明输入框，可再修改 |

“总结当前笔记”“AI 整理结构”也注册为命令，默认无快捷键，可自定义。

#### AI 整理结构

- 只调整结构（标题层级、分段、列表化），不增删观点；Front Matter、双向链接、图片与附件引用、代码块不允许改动。
- 生成后打开**左右对比**弹窗（左原文、右整理后，差异高亮），确认后才替换。
- 程序自动核对上述不可改动的内容数量与原文是否一致：一致时显示“核对通过”；不一致时标红说明缺了什么，“替换”不可用，只能重新生成或放弃。
- 替换前存一份历史快照（5.8），替换算一步操作，可撤销。
- 笔记超过单次请求的长度上限时直接提示“笔记过长”，不分段处理。

### 5.17 AI 对话

> 2026-09-28：取消原“书籍课程”需求，改为类似 ChatGPT 的对话界面。

#### 入口与布局

- 左栏最底部固定一行“AI 对话”。点击后左栏切换为**会话列表**，右侧编辑区打开“AI 对话”标签页；点左栏顶部其他视图图标或切到笔记标签页即回到笔记。
- 会话列表：顶部“新对话”按钮；会话按“今天 / 昨天 / 更早”分组，最新的在前；每个会话右侧“更多”菜单：重命名、删除（删除前确认）。新会话用第一条消息自动命名。
- 对话标签页：顶部是会话标题；中间是消息列表；底部是输入框，输入框右下角发送按钮左侧是模型切换下拉（列表来自设置里的模型，只影响当前会话），输入框下方是上下文用量。
- 未配置 AI 时点“AI 对话”，先提示“尚未配置 AI”（同 5.16）。

#### 发送

- 输入框：Enter 发送，Shift+Enter 换行；生成中发送按钮变为“停止”。
- 附件（每条消息可以有多个，发送前可以移除）：
  - **图片**：png、jpg、webp、gif，可粘贴、拖入或点回形针按钮选择；以 OpenAI 兼容格式（base64 图片）发送，需要模型支持识图。
  - **文本类文件**：txt、md、csv、json 与常见代码文件，读取内容后作为文字附在消息里。
  - **引用笔记**：输入 `@` 按笔记名模糊搜索，回车引用，发送时附上笔记正文。
  - 不支持 PDF、Word（后续版本）。
- 单个文本附件上限 1 MB、单张图片上限 10 MB，超过时提示，不添加。
- 只在用户点击发送时发送；发送的内容就是用户看到的消息和附件。

#### 回复

- 流式显示，按 Markdown 渲染（标题、列表、表格、行内代码、代码块高亮），不执行 HTML。
- 每条回复下方：复制、插入到笔记（插到最近编辑的笔记的光标处；没有打开的笔记时不可用）、保存为新笔记（在文件树当前文件夹新建，标题取回复第一行）。最后一条回复还有“重新生成”，并显示所用的模型名。
- 请求失败时，在回复位置显示原因并提供“重新生成”；消息带图片且失败时，额外提示“当前模型可能不支持图片，可以切换到支持识图的模型”。
- 第一版不做：编辑历史消息后分叉、搜索会话、联网搜索、语音、生成图片。

#### 上下文

- 每个会话都是独立的上下文，只带本会话的消息；新建会话即从空白上下文开始。
- 每次请求带上系统提示词和本会话从最近往前的历史消息，总量不超过**当前所选模型**的可发送上限（计算方式见 5.16）；更早的消息不发送，并在消息列表中显示分隔线“更早的 N 条消息未发送给 AI”。切换模型后上限随之变化。
- 输入框下方显示上下文用量进度：“上下文 约 12.3K / 131K tokens”（分母是当前模型的上下文长度），包含本次待发送的内容；到达可发送上限时进度条变色并注明“更早的消息不再发送”。图片不计入估算。

#### 存储

- 会话保存在本机应用数据目录（每个会话一个 JSON 文件，图片另存为文件），**不随笔记库同步**，不进入笔记库和搜索索引。
- 删除会话会删除其消息与图片；已插入或保存到笔记的内容不受影响。
- 日志中不记录对话内容。

## 7. 非功能需求

### 7.1 性能指标

基准：Windows 10/11，**1 万篇笔记（以图片附件为主）**的笔记库。

| 指标 | 目标 | M10 实测（2026-09-28） |
| --- | --- | --- |
| 冷启动到可编辑 | < 1 秒（索引已存在时） | 445ms |
| 空闲内存（Spark 进程 + 页面进程） | < 100MB | 46MB |
| 打开万篇笔记库后内存（Spark 进程 + 页面进程） | < 200MB | 99MB |
| 全文搜索响应 | < 200ms | 8–199ms（启动后第一次查询最慢） |
| 打开单篇笔记（< 100KB） | < 100ms | 75–93ms |
| 打开单篇笔记（约 1MB） | < 0.5 秒 | 约 400ms |
| 输入延迟 | 无可感知卡顿（< 16ms） | 约 1MB 的笔记中连续输入，帧间隔 16.7ms，无掉帧 |
| 首次建立 1 万篇索引 | 后台进行，不阻塞编辑 | 3–9 秒（取决于文件是否已在系统缓存中），期间打开笔记不受影响 |
| 安装包体积 | < 20MB | MSI 4.7MB，NSIS 3.5MB |

- 内存口径（2026-09-28 调整）：只统计 Spark 进程和 WebView2 的页面（renderer）进程。WebView2 运行时的公共进程（GPU、浏览器主进程、工具进程）不论界面内容都约占 150MB，属于系统组件开销，单独记录，不计入指标：M10 实测不打开笔记库时合计 196MB、打开万篇笔记库后合计 262MB。
- 打开单篇笔记（2026-09-28 调整）：原指标“< 1MB 的笔记 < 100ms”拆为两档。读取约 1MB 的文件只需约 10ms，其余时间是编辑器解析与渲染全文。
- 测量方法：`scripts/perf/` 中的脚本生成 1 万篇笔记（一半带图片）的测试库，用发布版经 WebView2 远程调试接口测量，见 README“性能验收”。

实现要求：

- 文件树虚拟滚动，大目录不卡顿。
- 索引、同步、文件监听在 Rust 侧后台线程执行。
- 编辑器的非必需模块按需加载。

### 7.2 可靠性

- 任何情况下不丢用户数据：原子写入、冲突两份都保留、删除进回收站、历史快照。
- 错误不吞：所有失败都向用户明确提示，并写入本地日志。
- 应用崩溃后重启，未保存内容可恢复。

### 7.3 兼容性

- 笔记文件为标准 Markdown，可被其他 Markdown 工具直接打开与编辑。
- 外部修改笔记文件时自动检测并刷新；若当前笔记有未保存修改，提示用户选择。

### 7.4 安全

- WebDAV 密码与 AI 的 API Key 仅存系统凭据库。
- 日志中不记录密码、API Key、笔记内容和发给 AI 的内容。
- 笔记内容只在用户主动点击 AI 功能时发送给用户配置的服务商（见 5.16）。
